# AI 产品工厂｜Harness 改进迭代方案

> 文档状态：待产品负责人确认
>
> 依据：`docs/28-Codex-App-Server架构迁移技术适配声明.md`、`docs/29-Codex-App-Server迁移第一阶段开发文档.md`、`agent-blueprint/BLUEPRINT.md`、`CONTEXT.md` 及与产品负责人的逐项核对。
>
> 定位：把产品工厂现有的 Harness 从"骨架已对、自觉性缺失"补齐到"可自主返工、可审批、可恢复、可独立验收"。

---

## 一、这份方案解决什么问题

把工厂 Agent 想成一名**会干活的工人**：他有工具箱（工具），也有安全规矩（权限）。对照 `agent-blueprint` 的 Harness 标准逐项核对后，结论是：

- **骨架对了**：工人、工具箱、安全规矩都在。
- **但工人还不会"自己把活干到合格为止"**：干一轮就交差，危险的事不会停下来问，很多规矩还停留在图纸上。

本方案就是把这些缺的"自觉性"分阶段补上。**补法只有一个总原则：不指望工人变聪明，而是加"规矩"逼他做到。**

---

## 二、现状诊断（大白话）

### 已经有的

- 有工人（Codex App Server 驱动）、有工具箱（受控工具）、有安全规矩（P0–P3 权限分级）。
- 有账本（SQLite 记录事件），刷新、断线后能看到历史。
- 有"做完一轮要交给你确认"的闸门。
- 素材工位不会造假：没有真实能力就明确阻塞。

### 缺的（按重要性排序）

| 序号 | 缺什么（大白话） | 对应技术点 | 优先级 |
| --- | --- | --- | --- |
| 1 | 工人只会干一轮，不会自己返工 | Agent Loop 缺 continue 闭环 | P0（最要紧） |
| 2 | 危险动作不会"停下来问你"，只会直接拒绝 | P2 权限缺人工审批管道 | P0 |
| 3 | 判断"成没成"没有独立检查员，还和工人混在一起 | Goal Gate 不是独立判断器 | P1 |
| 4 | 干到一半断电，不能可靠地接着干 | Task System + Workflow 缺依赖图、租约、检查点、journal | P1 |
| 5 | 各种小关卡（记账、脱敏、防越界）东一处西一处写，没统一 | Hooks 不是独立扩展点 | P1 |
| 6 | 长篇大论会占满脑子，没有自动清理 | Context Compact 没实现 | P2 |

> 说明：Subagent、Memory、Agent Teams、Cron、MCP 等组件之前已决定"暂缓或不采用"，本方案**不改变这些决定**，也不会新增外部平台、付费服务或真实发布。

## 三、逐条怎么补

### 缺口 1：让工人学会返工（P0，最优先）

**现象**：工人干一轮就交差，检查发现没做好，他就说"失败了"，停下来等你。现在那点"改错了再改回来"的能力，是靠任务里手把手写清楚让他做的，不是他自己会。

**补法**：给工人套一个由"规矩"自动转动的检查循环：

```
让工人干活
   ↓
独立检查：做好了吗？
   ↓
没做好 → 把"哪里没做好"告诉他 → 自动让他再干一轮
   ↓
做好了 → 才算完
```

**关键约束**：

- 循环由代码转，不靠工人自觉。
- 必须设"最多干几轮"的上限，防止无限循环烧钱。
- 每轮的结果都记进账本，不能覆盖上一轮。

**做完长什么样**：给工人一个"会失败的活儿"，他能自己经历"干 → 查 → 失败 → 改 → 再查 → 通过"，全程不打扰你，直到达标或轮数用尽。

---

### 缺口 2：让危险动作"停下来问你"（P0）

**现象**：工人要删文件、要花钱，现在直接说"不行，你重新来"。不会停下来征求你的同意。

**补法**：把"直接拒绝"改成"挂起 + 问你"：

```
工人要干危险的事
   ↓
规矩拦住他，把整个活暂停
   ↓
页面上给你看：他想干什么、影响什么、能不能反悔、要花多少钱
   ↓
你点"同意" → 他才继续干这一件事
你点"拒绝" → 这件事作废，工人换别的路
```

**关键约束**：

- 暂停期间，工人的其他动作也停，不能绕过去。
- 你同意的是"这一件事"，换目标、换内容、换费用后必须重新问。
- 每次问与答都记进账本，能查。

**做完长什么样**：工人碰到删除/花钱/对外发送，页面弹出确认，你点头他才动，拒绝他就换路，全程留痕。

---

### 缺口 3：独立检查员（P1）

**现象**：现在"成没成"的判断只是查一查有没有记录、文件对不对得上，没有独立的"这件事到底有没有达到目标"的判断器，也不管"目标根本做不到"的情况。

**补法**：把"判断成没成"交给一个**独立检查员**，和工人分开：

- 检查员只看账本里的真实记录，不听工人自夸。
- 检查员能给出四种结论：继续干 / 成了 / 失败了 / 目标做不到、交还给你。
- 目标根本做不到、预算用光、轮数用完时，检查员要如实交还控制权，不能假装成功。

**做完长什么样**：工人说"我做完了"，但检查员发现没证据，会继续让他干；目标本身做不到时，检查员会停下来告诉你"这事做不了"。

---

### 缺口 4：干到一半断电能接着干（P1）

**现象**：现在有账本，但"每一小步的依赖关系、谁正在干、干到哪一步了"记录不完整，重启后可能从头再来或重复干活。

**补法**：让工人每干完一小步就记一笔账，重启后看账本，从上次安全的位置接着来：

- 每件活记清楚：靠谁、下一步是谁、干到哪了。
- 同一件活同一时间只让一个人干，防止重复。
- 恢复前先查"上一件是不是已经干过了"，避免重复扣费、重复发布。

**做完长什么样**：工人干到一半，你关掉电脑重开，他从上次安全位置接着干，不从头重复，也不丢进度。

---

### 缺口 5：统一小关卡（P1）

**现象**：记账、脱敏、防越界这些检查，现在东一处西一处地写，容易漏、容易不一致。

**补法**：把这些检查做成**统一的小关卡**，每个工具进出都要过一遍：

- 进工具前：过一道"能不能干"的关卡。
- 出工具后：过一道"把结果和账记好"的关卡。
- 规则集中在一处，改一处全生效，不散落。

**做完长什么样**：新增一个工具时，不用在每个地方重复写检查，只要挂上统一的关卡，记账、脱敏、防越界自动生效。

---

### 缺口 6：自动清记录（P2）

**现象**：三份手册很长，干活还会产生一大堆工具结果，占满工人的"脑子"（上下文），现在没有任何清理机制。

**补法**：自动清理不重要的旧记录，但永远保留最重要的：

- 旧的大段工具结果，先转存成档案再清出脑子。
- 普通的聊天历史可以摘要。
- **三份手册、当前目标、重大决定、未解决的错误，永远不许删。**

**做完长什么样**：长任务跑很久，工人不会因为脑子满了而忘记目标或丢失关键决定。

---

### 缺口 7：危险动作开关绑在已确认步骤上（P2）

**现象**：现在危险程度中等的动作（改工作区、跑命令），放不放行是靠"手工开一个开关"，没绑在你已经确认过的步骤上。

**补法**：把开关改成**自动跟着你确认过的步骤走**：

- 你确认了"可以开工"这一步，这类动作才自动放行。
- 没确认、或确认过期了，这类动作自动挡住。

**做完长什么样**：你走到"开工"这一步并确认后，工人改代码、跑测试就自动放行；之前阶段他碰不了这些，不用每次手工开开关。

---

### 缺口 8：工具干完自动记账（P2）

**现象**：工具干完的结果，现在靠工人自己主动上报，靠事后核对文件来兜底，没有"干完自动记账"的机制。

**补法**：每个工具干完，系统**自动**记一笔"干了什么、结果怎样"，作为证据候选；工人不能只靠嘴说"我干完了"。

**做完长什么样**：只要工具真的执行过，账本里就自动有一条记录，检查员据此判断，而不是听工人一面之词。

---

## 四、迭代计划（分三阶段）

### 阶段一（P0）：把工人变成"会返工、会请示"的工人

包含：缺口 1、缺口 2。

**目标**：工人能自主"干到合格为止"，危险动作会停下来问你。

**验收**：

- 给工人一个会失败的活儿，他能自己完成"失败 → 修复 → 复测通过"的闭环，不打扰你。
- 工人碰到删除/花钱/对外发送，页面会弹出确认，你同意他才动，拒绝他就换路，全程留痕。
- 轮数用尽时如实停下来报告，不假装成功。
- 现有工程检查全部通过：`npm run lint`、`npm run typecheck`、`npm test`、`npm run test:e2e`、`npm run build:vefaas`、`npm run manuals:verify`。

### 阶段二（P1）：把"可靠性"和"独立验收"建起来

包含：缺口 3、缺口 4、缺口 5。

**目标**：有独立检查员、能断电续干、小关卡统一。

**验收**：

- 工人自夸"做完了"但没证据时，检查员会继续让他干。
- 目标本身做不到时，检查员停下来告诉你，不假装成功。
- 工人干到一半，重启后从安全位置接着干，不从头重复、不丢进度。
- 新增工具自动挂上统一关卡（记账、脱敏、防越界），无需重复写。

### 阶段三（P2）：把"耐用"做扎实

包含：缺口 6、缺口 7、缺口 8。

**目标**：长任务不丢关键信息、危险动作开关自动化、工具自动记账。

**验收**：

- 长任务跑很久，工人不会丢失目标、重大决定或未解决的错误。
- 走到"开工"并确认后，改代码/跑测试自动放行；之前阶段自动挡住。
- 工具只要真执行过，账本里就自动有记录。

## 五、明确不做（保持之前边界）

- 不改变"Subagent、Memory、Agent Teams、Cron、MCP 暂缓或不采用"的既有决定。
- 不新增付费平台、外部数据上传、云资源或真实发布。
- 不删除、覆盖或重建现有 SQLite 数据。
- 不修改三份原始手册，不破坏"每个新产品流程锁定快照、完成后释放"的规矩。
- 不把历史 G6–G9 验收记录改写为当前事实；新能力必须独立验收。

---

## 六、一句话总结

> 补的顺序：**先让工人会自己返工 → 再让危险事会问你 → 再让他能断电续干、有独立检查员 → 最后把杂七杂八的小关卡统一、开关自动化、记账自动化。**
>
> 每补一样，都是"加一条规矩"，不是"指望工人变聪明"。补完 P0 之后，工厂 Agent 才真正从"干一下就停的机器"变成"会干到合格为止的工人"。
