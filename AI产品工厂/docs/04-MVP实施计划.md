# AI 产品工厂｜MVP 实施计划 V0.1

> 实施状态：里程碑 1 已完成；里程碑 2 已完成 Agent Runtime、Pi 适配器、DeepSeek 配置、Worker 领单、事件持久化、SSE 和运行驾驶舱基础。缺少 Key 时的阻塞恢复已经验收，真实 DeepSeek 冒烟以及暂停、steer、继续、abort 和用量摘要尚待完成。

## 总体策略

不先做完整后台再寻找使用场景。收到小游戏 PRD 后，以它作为第一条真实纵向切片：每完成一段工厂能力，立即让小游戏生产链路穿过这段能力。同时用一个非游戏产品画像做蓝图编译回归，防止把试产对象误写成工厂内核。

## 里程碑 0：用小游戏冻结首条生产规格

### 目标

把小游戏 PRD 转成第一份真实项目生产档案，验证现有工位和质量闸门是否够用。

### 交付

- 小游戏产品范围确认单；
- 小游戏技术适配声明；
- 第一阶段开发文档；
- 首条完整生产路线和人工闸门位置；
- 工厂 MVP 数据 schema 修订版。
- 小游戏需要的能力包与通用基础工位之间的分界。

### 退出条件

用户确认产品范围、首个可玩闭环和发布目标。

## 里程碑 1：工厂骨架与项目接单

### 范围

- Monorepo、Web 和 Worker 基础工程；
- SQLite 生产档案；
- 新建项目、导入 PRD、选择工作区；
- 产品项目、生产批次、工位、生产单和生产事件的最小模型；
- 产品画像、生产蓝图编译器和能力包注册表；
- 项目总览页；
- DeepSeek 密钥服务端配置与连接测试。

### 可验收闭环

在 WebUI 创建“小游戏”项目，导入 PRD，系统生成并展示一张待执行生产单；刷新后内容仍在。

## 里程碑 2：Pi Agent 执行与实时驾驶舱

### 范围

- `AgentRuntime` 接口和 `PiAgentAdapter`；
- DeepSeek 模型配置档；
- Worker 领取生产单；
- Pi Agent 事件转换为生产事件；
- SSE 实时事件流；
- 暂停、steer、继续、abort；
- Token、耗时、错误和费用摘要。

### 可验收闭环

从 WebUI 启动“PRD 体检”工位，实时看见 Pi Agent 输出；刷新页面后恢复事件，用户可以补充指令并继续。

### 当前验证记录

- 已从 WebUI 创建并启动真实生产批次；
- Worker 成功领取生产批次；
- 未配置 `DEEPSEEK_API_KEY` 时，批次按 `run.created → run.claimed → agent.failed → run.blocked` 留下不可变事件并进入等待配置状态；
- 刷新运行页后状态和事件均可恢复；
- 390px 移动端运行页无横向溢出；
- 真实 DeepSeek 输出尚未冒烟，不能视为里程碑 2 全部完成。

## 里程碑 3：受控工具与检查点

### 范围

- 工作区读、写、搜索；
- 命令、Git 检查和测试工具；
- 工具权限策略和风险分级；
- 产物登记；
- 工位报告校验；
- Worker 崩溃和租约恢复；
- 高风险操作转人工闸门。

### 可验收闭环

Agent 在小游戏工作区生成第一阶段文档或代码；系统展示变更和检查结果。人为重启 Worker 后，生产批次从检查点继续且不重复破坏性操作。

## 里程碑 4：阶段编排与质量闸门

### 范围

- 生产控制器状态机；
- 接单体检、产品范围、技术适配、阶段设计、核心生产、综合质量工位；
- 四类人工闸门；
- 自动创建修复生产单；
- 测试、构建和 Playwright 结果采集；
- 发布候选判定。

### 可验收闭环

小游戏从 PRD 经过至少一个人工闸门和一个失败修复，最终成为发布候选；任何未通过的阻断质量项都不能被 Agent 自行跳过。

## 里程碑 5：首台小游戏完整试产

### 范围

- 用工厂完成小游戏核心闭环；
- 在浏览器真实试玩；
- 验证刷新、失败恢复和移动端目标；
- 生成完整生产档案、测试证据和发布候选；
- 按小游戏 PRD 决定是否进入真实部署。

### 小游戏试产完成条件

- 满足《产品定义》第 8 节全部成功指标；
- 用户确认工厂确实降低了从 PRD 到可玩产品的控制成本；
- 记录本次试产中无效工位、缺失工具和需要调整的闸门；
- 下一款产品无需改动核心状态机即可接入。

## 里程碑 6：跨产品通用性验证

### 范围

- 选择一个与小游戏明显不同的产品画像，例如 AI 内容工具或内部数据工作台；
- 编译并验证第二条生产蓝图；
- 确认第二条路线不会出现关卡、计分、帧循环等游戏专属要求；
- 确认新增产品差异只需要组合能力包，不修改生产控制器；
- 把试产中可复用的工位沉淀为通用基础工位，把游戏专属规则留在游戏能力包。

### 退出条件

同一工厂内核能够解释并调度两种不同产品蓝图。第二个产品可以只做到生产规划和骨架验证，不要求在第一轮就完整上线。

完成本里程碑后，才可以判定通用产品工厂 MVP 成立。

## 实施顺序上的硬约束

- 先做生产控制器和持久化，再做漂亮的实时界面。
- 先有内存 Agent 适配器测试，再接真实 Pi Agent + DeepSeek。
- 先限制工具权限，再开放写文件和 Shell。
- 先验证单批次可恢复，再考虑并行 Agent。
- 未收到小游戏 PRD 前，不猜它的玩法、框架、资产或上线平台。
- 不以“支持产品类型列表”代替产品画像；同一类别内部仍按真实能力需求编译蓝图。
