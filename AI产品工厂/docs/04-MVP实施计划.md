# AI 产品工厂｜MVP 实施计划 V0.2

> 状态：V0.2 方向、正式 PRD 和 G2–G4 已确认；G5–G6 未完成前不启动里程碑 3 的 Harness 改造。

> 实施状态：里程碑 1 已完成；里程碑 2 已验证 Pi Agent、DeepSeek、Worker、事件、SSE 和人工确认链路。Agent Blueprint 对照后确认，当前仍是“一张生产单对应一次模型生成”，尚未形成真正的 Agent Harness。V0.2 从里程碑 3 起以 Harness、Workflow Runtime 和 Goal Gate 为主线。

## 总体策略

不先做完整后台再寻找使用场景。收到小游戏 PRD 后，以它作为第一条真实纵向切片：每完成一段工厂能力，立即让小游戏生产链路穿过这段能力。同时用一个非游戏产品画像做蓝图编译回归，防止把试产对象误写成工厂内核。

## 里程碑 0：用小游戏冻结首条生产规格

### 目标

把小游戏 PRD 转成第一份真实项目生产档案，验证现有工位和质量闸门是否够用。

### 交付

- 小游戏产品范围确认单；
- 小游戏技术适配声明；
- 第一阶段开发文档；
- 首条完整生产路线和人工闸门位置；
- 工厂 MVP 数据 schema 修订版。
- 小游戏需要的能力包与通用基础工位之间的分界。

### 退出条件

用户确认产品范围、首个可玩闭环和发布目标。

## 里程碑 1：工厂骨架与项目接单

### 范围

- Monorepo、Web 和 Worker 基础工程；
- SQLite 生产档案；
- 新建项目、导入 PRD、选择工作区；
- 产品项目、生产批次、工位、生产单和生产事件的最小模型；
- 产品画像、生产蓝图编译器和能力包注册表；
- 项目总览页；
- DeepSeek 密钥服务端配置与连接测试。

### 可验收闭环

在 WebUI 创建“小游戏”项目，导入 PRD，系统生成并展示一张待执行生产单；刷新后内容仍在。

## 里程碑 2：Pi Agent 执行与实时驾驶舱

### 范围

- `AgentRuntime` 接口和 `PiAgentAdapter`；
- DeepSeek 模型配置档；
- Worker 领取生产单；
- Pi Agent 事件转换为生产事件；
- SSE 实时事件流；

### 可验收闭环

从 WebUI 启动“PRD 体检”工位，实时看见 Pi Agent 输出；刷新页面后恢复事件，用户可以补充指令并继续。

## 里程碑 3：最小 Agent Harness 与受控工具

### 范围

- 工作区读、写、搜索；
- 命令、Git 检查和测试工具；
- 单一 Agent Loop 和统一工具注册表；
- PreToolUse / PostToolUse Hooks；
- 工具权限策略和风险分级；
- Todo 计划与工具调用/结果配对；
- 三份手册的 ManualAuthority：哈希校验、完整加载和受保护上下文；
- 可恢复大输出、按需 Skill 和普通会话上下文压缩；
- 产物登记；
- 工位报告校验；
- 高风险操作转人工闸门。

### 可验收闭环

Agent 在独立试验工作区连续完成“读取 → 修改 → 运行测试 → 根据失败修复 → 重新验证”，系统展示计划、工具动作、变更和证据。越界写入与高风险命令被确定性权限管线阻止。

## 里程碑 4：可恢复 Workflow 与 Goal Gate

> 当前进度：其中的规划阶段状态和两道人工确认闸门已提前落地；自动检查、修复生产单、发布候选判定和完整工位链路尚未完成。

### 范围

- 生产控制器状态机与 Workflow Definition registry；
- 持久 Task DAG、依赖与单写入认领；
- Workflow journal、稳定调用键、暂停、继续、终止和崩溃恢复；
- 安装、构建、测试和浏览器验收的后台任务；
- 独立 Goal Gate，根据真实证据决定继续或完成；
- 接单体检、产品范围、技术适配、阶段设计、核心生产、综合质量工位；
- 四类人工闸门；
- 自动创建修复生产单；
- 测试、构建和 Playwright 结果采集；
- 发布候选判定。

### 可验收闭环

同一测试工作流中断并恢复后不重复已完成副作用；模型停止调用工具但证据不足时，Goal Gate 会要求继续或转为阻塞。小游戏从 PRD 经过至少一个人工闸门和一个失败修复，最终成为发布候选。

## 里程碑 5：首台小游戏完整试产

### 范围

- 用工厂完成小游戏核心闭环；
- 在浏览器真实试玩；
- 验证刷新、失败恢复和移动端目标；
- 生成完整生产档案、测试证据和发布候选；
- 按小游戏 PRD 决定是否进入真实部署。

### 小游戏试产完成条件

- 满足《产品定义》第 8 节全部成功指标；
- 用户确认工厂确实降低了从 PRD 到可玩产品的控制成本；
- 记录本次试产中无效工位、缺失工具和需要调整的闸门；
- 下一款产品无需改动核心状态机即可接入。

## 里程碑 6：跨产品通用性验证

### 范围

- 选择一个与小游戏明显不同的产品画像，例如 AI 内容工具或内部数据工作台；
- 编译并验证第二条生产蓝图；
- 确认第二条路线不会出现关卡、计分、帧循环等游戏专属要求；
- 确认新增产品差异只需要组合能力包，不修改生产控制器；
- 把试产中可复用的工位沉淀为通用基础工位，把游戏专属规则留在游戏能力包。

### 退出条件

同一工厂内核能够解释并调度两种不同产品蓝图。第二个产品可以只做到生产规划和骨架验证，不要求在第一轮就完整上线。

完成本里程碑后，才可以判定通用产品工厂 MVP 成立。

## 里程碑 7：按真实需要扩展 Agent 能力

只有前述单 Agent 生产闭环稳定后，才逐项评估：

- 一次性 Subagent：隔离审查、调研或大上下文子任务；
- Memory：跨会话保留稳定偏好和项目事实；
- Agent Teams + worktree：确有并行收益且冲突边界清晰时启用；
- MCP：目标产品需要外部系统时按宿主权限策略接入；
- Cron：出现明确的定时生产或巡检需求时启用。

这些组件不是 V0.2 成立的前置条件，不为追求 17 个组件齐全而加入。

## 实施顺序上的硬约束

- 先做生产控制器和持久化，再做漂亮的实时界面。
- 先有内存 Agent 适配器测试，再接真实 Pi Agent + DeepSeek。
- 先限制工具权限，再开放写文件和 Shell。
- 先让一个 Agent 在一个工作区可靠完成闭环，再增加 Subagent 或 Agent Teams。
- 固定生产阶段写入 Workflow；阶段内不确定动作交给 Agent Loop，二者不得互相吞并。
- 三份原始手册完整读取并受保护，Skill 目录和摘要只能导航，不能替代原文。
- 先验证单批次可恢复，再考虑并行 Agent。
- 未收到小游戏 PRD 前，不猜它的玩法、框架、资产或上线平台。
- 不以“支持产品类型列表”代替产品画像；同一类别内部仍按真实能力需求编译蓝图。
