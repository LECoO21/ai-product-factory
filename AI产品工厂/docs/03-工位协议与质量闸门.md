# AI 产品工厂｜执行合同与质量闸门 V0.2

> 状态：执行合同方向、正式 PRD 和 G2–G5 已确认；当前只冻结 V0.2-B 最小 Harness 的 G6 生产单、完成目标和验收，不开放生产代码写入。

## 1. 设计原则

工位不是一段角色 Prompt，也不等于一次模型调用，而是一份可验证的阶段职责合同。每次执行前生成生产单和完成目标；Workflow Runtime 可以在同一工位内驱动多轮 Agent、多个任务和多个工具调用，执行后生成工位报告。生产控制器只根据结构化结果、质量证据和人工决定流转状态。

模型可以提出下一步建议，但不能自行宣布质量闸门通过，也不能绕过人工闸门。

## 2. 生产单

```ts
type WorkOrder = {
  id: string;
  projectId: string;
  runId: string;
  blueprintId: string;
  stage: StageName;
  station: StationName;
  objective: string;
  inputs: ArtifactRef[];
  constraints: string[];
  allowedTools: ToolGrant[];
  modelProfile: string;
  tokenBudget?: number;
  costBudgetCny?: number;
  timeoutMinutes: number;
  acceptanceCriteria: AcceptanceCriterion[];
  completionGoal: CompletionGoal;
  workflowDefinition: WorkflowDefinitionRef;
  expectedArtifacts: ExpectedArtifact[];
  humanGatePolicy: HumanGatePolicy;
};
```

生产单必须回答：做什么、为什么做、允许动哪里、不能做什么、什么算完成、需要留下什么证据。

`completionGoal` 必须同时写明结束状态、验证方式和限制条件。Agent 停止调用工具不能代替完成目标。

## 3. 工位报告

```ts
type StationReport = {
  workOrderId: string;
  outcome: "completed" | "blocked" | "failed" | "cancelled";
  summary: string;
  artifacts: ArtifactRef[];
  changedFiles: string[];
  checks: CheckResult[];
  assumptions: string[];
  knownIssues: KnownIssue[];
  requestedGate?: GateRequest;
  recommendedNextAction: string;
};
```

报告中的 `completed` 只代表工位自报完成，必须经过对应质量闸门才变成 `passed`。

## 4. 第一版工位目录

| 工位 | 主要输入 | 主要产物 | 通过条件 |
| --- | --- | --- | --- |
| 接单体检 | PRD、工作区、三份手册 | 资料体检、缺失项、项目生产单 | 输入可追溯；重大缺失已提出 |
| 产品范围 | 体检结果、PRD | 产品范围确认单、核心闭环、明确不做 | 产品范围人工闸门通过 |
| 技术适配 | 范围确认单、现有代码 | 技术适配声明、开发路径、阶段路线图 | 强制底线和偏离项完整 |
| 阶段设计 | 当前阶段目标 | 阶段开发文档、状态机、接口与验收项 | 契约完整且无越界范围 |
| 核心生产 | 阶段文档、代码 | 后端/Agent 能力、测试、最小界面 | Mock 测试和真实模型冒烟达标 |
| 效果验收 | 真实输入与真实产物 | 效果报告、成本和质量记录 | Agent 效果人工闸门通过 |
| 前端生产 | 已验收接口、视觉输入 | 正式前端、状态矩阵、E2E | 真实闭环和目标尺寸可用 |
| 综合质量 | 完整产品 | 测试报告、浏览器证据、已知问题 | 所有阻断项清零或明确接受 |
| 发布准备 | 发布候选、部署约束 | 部署方案、回滚方案、发布清单 | 发布人工闸门通过 |
| 部署验收 | 已批准发布候选 | 访问地址、登录、监控和恢复证据 | 线上核心闭环通过 |

小游戏试产可以按真实复杂度合并“核心生产”和“前端生产”，但不得跳过效果验收和综合质量。

这张表是通用基础工位，不是所有项目必须机械执行的固定直线。生产蓝图可以合并、跳过或增加工位，但必须保留与当前产品风险相匹配的质量证据。例如不含模型调用的普通小游戏不需要“真实模型效果验收”，但仍需要真实试玩验收；包含 RAG 的知识工具则必须增加检索质量检查。

工位目录由 Workflow Definition 编排。固定阶段和依赖写在代码与版本化定义中；工位内读取哪些文件、运行哪些检查、如何修复失败，由 Factory Agent 根据工具观察动态决定。

### 4.1 能力包如何扩展工位

能力包只能通过以下方式扩展流水线：

- 增加工位或为基础工位追加验收条件；
- 授予明确的新工具权限；
- 增加产物类型和质量检查器；
- 增加需要人工判断的产品体验闸门。

能力包不能直接改变生产控制器状态，也不能降低安全、可恢复和真实性底线。

## 5. 固定质量闸门

### QG-01 输入完整性

- PRD、当前工作区和用户约束已登记；
- 未确认假设明确标记；
- 不把模型生成的猜测当作用户要求。

### QG-02 变更安全

- 修改范围位于授权工作区；
- 已检查 Git 与未提交修改；
- 密钥未进入仓库、前端、日志和产物；
- 无未经批准的破坏性操作。

### QG-03 核心能力

- 状态、错误和恢复路径已实现；
- 自动测试通过；
- 涉及 Agent 时完成真实 Codex App Server Turn 与所需工具调用冒烟；
- 真实输入能得到可查看产物。

### QG-04 前端闭环

- 真实接口而非最终 Mock；
- loading、empty、running、waiting、failed、succeeded 和恢复状态按需覆盖；
- 刷新后按任务 ID 恢复；
- 防重复提交；
- 桌面和移动端核心流程可操作。

### QG-05 发布候选

- Lint、类型检查、测试和构建通过；
- Playwright 核心闭环通过；
- 浏览器 Console 无持续错误；
- 已知问题、影响和回退方式完整；
- 访问凭证与部署配置没有泄漏。

### QG-06 完成目标证据

- Goal Gate 与主执行 Agent 分离；
- 完成判断引用已登记的命令、退出码、测试、构建、浏览器或人工证据；
- 后台任务未结束时暂缓判断，不把“正在运行”当成完成；
- 证据不足时继续执行或交还用户，不能把模型自述当作通过；
- 达到轮数、时间或预算上限时如实进入阻塞，不伪装成功。

## 6. 人工闸门请求格式

```ts
type GateRequest = {
  type:
    | "prd"
    | "technical_adaptation"
    | "domain_model"
    | "component_selection"
    | "product_blueprint"
    | "stage_start"
    | "product_quality"
    | "frontend_quality"
    | "release"
    | "major_impact";
  title: string;
  decisionNeeded: string;
  evidence: ArtifactRef[];
  recommendedOption: string;
  options: Array<{
    id: string;
    label: string;
    impact: string;
  }>;
  irreversible: boolean;
  costImpactCny?: string;
};
```

WebUI 必须展示“为什么现在需要决定、推荐什么、不同选择的影响、是否可撤销”。用户可批准、拒绝或补充说明，决定本身写入生产事件。

前九种类型对应 PRD 的 G1–G9 固定阶段闸门；`major_impact` 是任何阶段都可触发的横切安全闸门，不替代固定阶段确认。

## 7. Harness 上下文组成

每次 Agent 执行的上下文由权威通道和任务通道组成：

1. 使用当前产品流程开始时已完成 SHA256 校验、按固定顺序完整读取并锁定的三份原始手册快照；
2. 同一流程的所有工位、返工、重试和恢复只复用该快照，不重新读取磁盘原文；流程完成或终止后释放且不再读取，下一个新产品流程重新校验并完整读取；
3. 工厂强制规则、当前工位职责和禁止事项；
4. 当前生产单、完成目标和 Workflow 状态；
5. 相关 PRD、适配声明和阶段文档；
6. 工作区的最小必要上下文；
7. 工具说明、权限、预算和工位报告 schema。

不要把整个项目历史和全部能力包无差别塞给模型。由上下文构建器按需选择项目产物和 Skill。超长会话先转存大工具结果、保留最近观察，再摘要普通历史；当前产品流程已锁定的三份原始手册快照属于受保护权威上下文，不得被摘要、裁剪或派生文档替代。

## 8. 失败、重试和恢复

- 工具失败：保留错误证据，允许 Agent 在预算内有限重试。
- 模型失败：区分认证、限流、超时、结构错误和内容质量问题。
- Worker 崩溃：通过租约超时回收生产单，从最近检查点恢复。
- Workflow 中断：从 journal 恢复已完成的确定性步骤，稳定调用键命中的结果不重复执行。
- 后台任务失败：写入完成通知和退出证据，由 Agent 决定修复或升级，不阻塞无依赖任务。
- 质量闸门失败：创建修复生产单，不覆盖原失败证据。
- 用户退回：原决定和补充意见都保留，生成新的工位版本。
- 连续失败超过策略阈值：进入 `blocked`，向用户说明阻塞事实和推荐动作。

## 9. 版本与可追溯性

每个产物至少关联：

- 产品项目与生产批次；
- 生产单和工位版本；
- 模型供应商、模型标识和关键参数；
- 输入产物版本；
- 代码提交或 diff；
- 检查结果；
- 创建时间。

Prompt、工位说明和 schema 作为版本化文件管理。生产批次一旦开始，不因模板后来更新而悄悄改变历史执行含义。
