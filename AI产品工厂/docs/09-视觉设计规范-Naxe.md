# Naxe 视觉设计规范 V1.6

> 适用范围：AI 产品工厂 WebUI，包括首页、项目详情页和生产运行台。当前个人版不展示登录与退出入口。
>
> 本版视觉参考：保留中性浅色、紧凑控件、细线图标和克制动效；按用户要求，整体工作台直接铺满视口，不套外层卡片。方案产出及后续生产环节采用参考图 2 的 ChatGPT 式连续对话结构，所有交流、结果、记录与确认在同一条对话中展示。
>
> 参考边界：只借鉴布局比例、信息层级和交互语言；不复制参考图的品牌、3D 角色、素材、文案或专有图标。保留 Naxe 原创品牌和产品业务契约。

## 1. 品牌

- 对外名称：`Naxe`。
- 产品描述：`AI 产品生产工作台`。
- 语气：冷静、简洁、准确，优先说明当前状态和下一步动作，不使用宣传性技术口号。
- 流程与结果标题直接描述任务或内容，如“需求分析”“技术方案”“开发计划”“产品实现结果”“上线方案”；不用“接单体检”等工厂化比喻。专业名词与产品自身的业务术语按原意保留。
- Logo：使用现有原创像素 `N`。两条竖向结构代表稳定的生产边界，中间阶梯状对角线代表产品逐步流转。

### Logo 使用

- 默认图形尺寸 20×20px，最小 16×16px。
- 左栏中可放入 32×32px 的对齐区，但不为 Logo 额外增加强调容器。
- 只使用单色：浅色背景用近黑，深色背景用近白。
- 不添加渐变、装饰投影、额外描边或模仿参考图的外形。
- 图形与 `Naxe` 文字的默认间距为 8px。

## 2. 设计原则

1. **对话优先**：方案产出工作区以连续对话为主，需求、AI 结果、用户补充、确认与运行记录按发生顺序保留；详细过程可在对话中展开。
2. **全屏工作台**：应用直接铺满视口，整体外框、运行页顶栏与对话主区域不使用卡片式边框、圆角或投影。
3. **紧凑但可读**：使用创作软件式的中高信息密度，但正文不小于 13px，关键状态和动作不能难以识别。
4. **全无衬线**：品牌、标题、正文和控件统一使用现代无衬线字体，不再使用首页衬线标题。
5. **层级靠明度和分隔**：侧栏分隔、纯白工作区与浅灰消息气泡建立层级。输入器、确认卡片等局部组件保留必要边界，内容卡片默认不反复叠加投影。
6. **状态真实**：动画、颜色和前端计时不得替代后端真实状态。没有可确认结果时不显示确认动作。
7. **响应式重排**：桌面端保留产品侧栏与单列对话区；窄屏侧栏变为抽屉，对话独立滚动，底部输入框始终可触达。

## 3. 色彩系统

### 中性色

| Token | 建议值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#F0F0EF` | 暖灰基础色，不作为包围工作台的外边距 |
| `--shell` | `#FBFBFA` | 主应用与侧栏浅色底色 |
| `--surface` | `#FFFFFF` | 对话主区域、输入器、浮动工具条和弹层 |
| `--surface-subtle` | `#F7F7F5` | 主工作区域和轻分区 |
| `--surface-muted` | `#F1F1EF` | 用户消息气泡、侧栏和选中区域 |
| `--surface-hover` | `#ECECEA` | 导航、列表和次按钮 hover |
| `--surface-pressed` | `#E5E5E1` | 按下和持续激活状态 |
| `--ink` | `#171716` | 主文字和主图标 |
| `--ink-secondary` | `#5F5F5B` | 次要文字，需满足正文对比度 |
| `--ink-tertiary` | `#777771` | 非关键辅助信息 |
| `--line` | `#E7E7E3` | 普通分隔线和控件边框 |
| `--line-strong` | `#D8D8D3` | 选中和强边界 |

### 状态色

| Token | 文字/图标 | 浅色背景 | 用途 |
| --- | --- | --- | --- |
| `--success` | `#3E7345` | `#EAF3EB` | 已通过、已完成 |
| `--warning` | `#805D28` | `#F8F0DF` | 等待确认、部分完成 |
| `--danger` | `#9C4138` | `#F8EAE8` | 错误、失败、终止 |

- 主交互以近黑和近白为主，状态色只用于有业务含义的小面积提示。
- 所有状态同时显示文字或图标，不只靠颜色区分。
- 禁止在页面组件中继续新增无语义的灰色或透明度值。

## 4. 字体与字号

### 字体栈

- 界面统一使用：`-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif`。
- 只在纯技术内容中使用：`SFMono-Regular, Consolas, monospace`。
- 不引用项目没有实际加载的字体名称，不下载参考产品的商业字体。
- 中英文使用同一组视觉层级；字重主要使用 400、500 和 600，避免大面积粗体。

### 字号层级

| 层级 | 桌面 | 手机 | 字重/行高 |
| --- | --- | --- | --- |
| 页面主标题 | 22–24px | 22px | 600 / 1.25 |
| 工作区标题 | 15–18px | 17–18px | 600 / 1.35 |
| 面板标题 | 13–14px | 14px | 500–600 / 1.4 |
| 正文 | 13–14px | 14px | 400 / 1.55–1.7 |
| 对话及方案正文 | 14px | 14px | 400 / 1.8 |
| 按钮与导航 | 12–13px | 13–14px | 500 / 1 |
| 状态与辅助信息 | 11–12px | 12px | 400–500 / 1.45 |
| 技术日志 | 11–12px | 12px | 400 / 1.6 |

- 10px 只可用于非必要的视觉标记，不用于需要阅读或操作的信息。
- 长文结果与对话使用居中的约 800px 内容列，避免宽屏内容过宽导致阅读困难。
- 对话工作区的状态、时间与过程记录不小于 11px；手机输入框使用 16px，减少输入时浏览器自动放大的干扰。

## 5. 图标

- 通用界面图标统一使用 `Lucide`，不混用表情符号、字体符号和多套 SVG 风格。
- 默认图标尺寸 16px，紧凑辅助操作 14px，主要操作最大 18px。
- 默认 `stroke-width: 1.6`；小尺寸图标可提高到 1.75，但同一工具组必须一致。
- 图标与文字默认间距 7px；图标在 32–36px 的桌面控件中光学居中。
- 仅图标按钮必须有可访问名称，并在桌面 hover/focus 时提供工具提示。
- Naxe BrandMark 是品牌图形，是唯一不受 Lucide 限制的常驻图形。

## 6. 形状、边框与投影

### 圆角

| 层级 | 圆角 |
| --- | --- |
| 应用整体、运行页顶栏和对话主区域 | 0 |
| 主面板、大型输入器 | 14–16px |
| 对话输入器 | 桌面 22px；手机 18px |
| 用户消息气泡 | 20px；右下角 5px |
| 按钮、输入框、列表选中项 | 8–10px |
| 小标签和状态块 | 6–8px |
| 胶囊状态、圆形图标按钮 | 999px / 50% |

- 不再将 16px 圆角一次性应用到所有导航、按钮和列表。
- 工具性控件优先使用 8–10px 圆角，保留紧凑、精密的视觉感受。

### 边框与投影

- 侧栏、分区和列表使用 1px 发丝分隔线，不用大面积深色边框。
- 应用整体、运行页顶栏和对话主区域不添加外框边线或投影，保留侧栏与工作区之间的分隔。
- 浮动工具条、输入器或弹层可使用：`0 8px 24px rgba(31, 31, 27, 0.08)`。
- 一般内容面板不使用投影，通过底色和边框与相邻区域分隔。

## 7. 桌面布局

### 应用外壳

- 应用宽度为 `100%`、高度为 `100dvh`，无整体外边距，不设 1600px 最大宽度。
- 整体无边框、圆角和投影，内部 `overflow: hidden`；运行页取消包围顶栏和对话区域的内边距与间隙，形成连续的纯白工作区。
- 顶栏与对话主区域不再分别套卡片；消息气泡、输入器、确认卡片及侧栏分隔保留各自样式。
- 产品侧栏与对话历史分别管理自己的滚动；顶部标题和底部输入框保留在视口内，长文结果不推动整个工作台。

### 对话工作台

| 区域 | 建议宽度 | 职责 |
| --- | --- | --- |
| 左栏 | 232px；中等桌面 208px；可收起为 64px | Naxe 品牌、新建产品、最近产品和个人工作台状态 |
| 对话工作区 | `minmax(0, 1fr)`；内容列最大约 800px | 连续展示需求、各阶段 AI 结果、过程记录、产物、用户补充与确认 |
| 底部输入区 | 与对话内容列同宽 | 当前阶段统一的补充回答、修改意见和调整指令入口 |

- 左侧保留产品历史和导航；对话区域使用 `--surface`。方案产出页不再保留右侧流程检查器。
- 顶部使用紧凑标题栏，展示产品名称、当前阶段和返回入口；阶段切换也在对话中以分隔标记显示。
- 用户消息右对齐，使用浅灰气泡；AI 结果左对齐，以可阅读的正文展开，避免把整段对话包成层叠大卡片。
- 底部输入器停靠在对话工作区下方，与历史滚动区并列布局；输入器不覆盖结果或确认按钮。
- 查看较早消息时不强制滚回底部；有新内容时提供“回到最新消息”入口，用户回到底部后继续跟随新增内容。

### 页面特例

- **首页**：保留中央需求输入和当前待办。最近产品只在左栏展示，不在输入器下方重复生成卡片网格。
- **访问入口**：当前个人版打开后直接进入首页，不展示登录页、登录按钮或退出按钮；备用认证页面不属于当前可见流程。
- **项目详情**：使用紧凑顶栏、批次列表和可折叠 PRD 资料区；批次最多展示 20 条并在区域内滚动。
- **生产运行台**：从初始需求开始，连续展示各阶段结果、用户修改、确认记录和当前任务状态；产物、验证结果与详细日志均置于相关消息内。

## 8. 组件规范

### 按钮和工具条

- 桌面默认高度 32–36px，带文字的主要按钮可使用 36px；手机端主要操作保持至少 44px 的可触达区。
- 左右内边距 12–14px，圆角 8–10px。
- 主按钮：`--ink` 底 + `--shell` 字；一个操作组中只保留一个强主按钮。
- 次按钮：`--surface` 底 + `--line` 边框；hover 时进入 `--surface-hover`。
- 破坏性操作使用危险色文字和边框，仍需显式确认。
- hover、focus、active、disabled 和 loading 必须使用同一套状态规则。

### 列表和导航

- 列表项默认高度 36–44px，紧凑日志行可根据内容自适应。
- hover 使用背景色和边框变化，不默认上移卡片或放大元素。
- 当前项使用 `--surface-muted`、500 字重和必要的文字状态，不只使用颜色差。
- 最近产品与工具记录按现有上限展示；对话中的过程记录默认展示最近 20 条，更早记录在同一对话中折叠保留。对话历史不得因切换阶段或重新分析而被当前结果替换。

### 首页需求输入器

- 使用 `--surface` 背景、1px 边框、14–16px 圆角和单层轻投影，不再使用 28px 大圆角灰色块。
- 输入方式切换使用紧凑分段控件，选中、hover 和键盘焦点必须可区分。
- 首页的文本区建议最小高度 88px。
- 发送按钮使用 36px 的圆形或 10px 圆角方形图标按钮；手机端增大可触达区。
- 提交后立即显示真实提交状态并禁止重复提交。

### 对话输入器

- 运行台使用一个统一输入框，位于对话区底部，与约 800px 的消息列对齐；无需进入独立侧栏填写反馈。
- 使用 `--surface-subtle` 背景、1px 边框、轻投影；文本区随可用空间收缩，长输入在框内滚动。
- 依据真实阶段说明输入用途：等待验收时用于补充回答或修改意见，执行中用于后端支持的调整指令。
- 发送按钮与输入辅助说明位于框底；可用时显示停止操作。执行、提交、等待确认、失败等状态必须真实反映到控件可用性。
- 提交失败保留输入；提交成功后，补充内容及其处理结果出现在对话历史中。

### 结果、验证和确认

- 结果作为 AI 消息在对话历史中直接展开；整个历史区域独立滚动，不为每条长结果再套一个滚动面板。
- 初始需求、各次结果、重新分析、用户反馈和已确认动作按顺序保留，刷新或进入下一阶段后仍可查看。
- 图片、音频、3D 和 HTML 等产物使用统一的预览、状态和打开入口，生成中不冒充最终产物。
- 产物链接与验证结果跟随对应 AI 消息展示；过程和工具记录在同一条消息下折叠展开。
- 等待确认时在相关结果下展示确认卡片，说明已完成内容、确认后会发生什么和主确认动作；修改或回答统一使用底部输入框，返回入口保持可达。
- 只有真实结果和必需产物已就绪时才显示确认按钮；等待过长、连接中断或动画结束都不能触发确认。
- 确认或提交修改意见后立即禁用对应按钮，防止创建重复 Run 或重复计费任务。
- 终止产品流程保留已有记录，但不再中央展示为可继续任务，也不显示重试。
- 上线流程只生成方案、检查和手工发布清单；最终状态明确写“发布候选”和“没有执行部署”。

## 9. Hover、Focus 与动效

### Hover 和按下

- 默认过渡时长 140–180ms，使用 ease-out；侧栏和抽屉可使用 180–220ms。
- hover 优先改变背景、边框或文字色；浮动输入器可小幅增强投影。
- 普通列表、导航和卡片 hover 时不放大、不旋转、不上浮。
- active 只允许颜色变化或最多 1px 的按压位移。
- 触摸设备不依赖 hover 才能发现关键功能。

### Focus

- 键盘焦点使用 2px `--ink` 外轮廓和 2px 偏移，或对比度不低于 3:1 的等价焦点环。
- 不用仅有 1px 灰色边框的变化作为唯一焦点提示。
- 输入器、分段控件、侧栏收展、详情折叠和所有主要动作都必须保留可见焦点。

### Reduced motion

- 必须遵守 `prefers-reduced-motion: reduce`，动画和过渡缩短到近似即时，并禁止非必要的位移、滚动和呼吸动画。
- 加载动效只表达“正在处理”，不模拟百分比、不推测完成时间。
- 页面切换不使用大幅位移或缩放；最多使用轻微透明度变化。

## 10. 响应式

### 默认验收宽度

- 390px：常见手机。
- 768px：平板或窄窗口。
- 1280px：常见桌面工作区。
- 1440px：宽屏桌面工作区。

### 重排规则

- 1024–1279px：左栏缩为 208px，对话工作区保持 `minmax(0, 1fr)`，内容列随可用宽度收缩。
- 900–1023px：左栏自动收为 64px 图标栏，对话区继续使用居中的单列结构。
- 900px 以下：左栏变为抽屉；关闭后遮罩不得残留点击层。整体继续铺满视口，不增加外边距或外壳圆角。
- 720px 以下：运行台仍由标题、可独立滚动的对话区和底部输入器组成，保持视口高度，不回退为无限拉长的整页布局；确认动作可占满容器宽度。
- 当前阶段由顶栏与对话内阶段分隔显示，不在窄屏水平挤入完整步骤导航。
- 键盘弹出时，底部输入和提交按钮必须仍可触达；底部留出设备安全区域。
- 所有页面不得出现无意的水平滚动，媒体预览、长文本和日志必须在自身容器内收缩或滚动。

## 11. 无障碍与业务状态

- 默认以 WCAG 2.2 AA 为最低基线：正文对比度至少 4.5:1，大字、非文本控件和焦点指示按相应规则至少 3:1。
- 核心操作可以全程通过键盘完成；表单有关联 Label，图标按钮有可理解的名称。
- 任务界面明确区分：未开始、提交中、排队、运行、流式输出、等待用户、成功、失败、已取消、断线恢复和状态过期。
- 加载、空数据和请求失败是三种状态，不得在接口返回前抢先显示“暂无产品”或“暂无产物”。
- 断线时明确说明“任务可能仍在继续”，重新读取后端状态；不鼓励用户重复创建任务。
- 运行记录、内部工具细节和调试信息默认折叠，普通用户先看结果、状态和下一步。

## 12. 视觉验收

每次修改全局外观、布局或交互后，至少完成：

1. 在 1440×900 和 390×844 的相同业务状态下对比界面。
2. 检查首页、项目详情和生产运行台，不只验收首页。
3. 检查左栏收起、手机抽屉、长对话与长结果、最近 20 条及更早日志的展开、输入法键盘和对话独立滚动。
4. 检查 hover、键盘 focus、active、disabled、loading、empty、failed、waiting-user、success 和 disconnected。
5. 确认浏览器 Console 无持续错误、页面无水平溢出、确认区不遮住结果。
6. 开启系统“减少动态效果”后重新检查页面，不得出现依赖动画才能理解或操作的内容。
