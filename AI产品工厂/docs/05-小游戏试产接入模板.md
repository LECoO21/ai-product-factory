收到小游戏 PRD 后，工厂先从 PRD 自动提取本模板内容；只有会显著改变玩法、成本、范围或发布目标的缺项才需要用户补充。

- 什么体验算“好玩”：

- 目标终端：桌面 Web / 移动 Web / 两者
- 核心操作：鼠标 / 键盘 / 触摸 / 重力感应 / 其他
- 目标屏幕方向：横屏 / 竖屏 / 自适应
- 是否需要声音、音乐、震动或全屏：

## 6. 技术与发布

- 已有代码：有 / 无

- 目标发布位置：本地演示 / 公网网页 / 指定小游戏平台
- 是否需要后端：由 PRD 指定 / 由技术适配判断
- 数据保留和隐私要求：

## 7. 验收

第一版至少要给出可操作标准：

- 玩家如何开始一局；
- 玩家如何完成核心操作；
- 哪个画面或状态证明一局完成；
- 重开、失败、刷新和异常时应发生什么；
- 桌面和手机各自需要验证什么；
- 哪些体验由产品负责人亲自判断，不能只靠自动测试。

## PRD 到达后的处理顺序

1. 完整读取 PRD 和参考资料；
2. 填充本模板，不让用户重复回答 PRD 已写清的内容；
3. 输出矛盾、重大缺失和推荐裁决；
4. 选择普通 Web 纵向切片、Canvas 游戏或其他适配路线；
5. 生成技术适配声明和第一阶段开发文档；
6. 产品范围人工闸门通过后，开始工厂 MVP 与小游戏的联合开发。
