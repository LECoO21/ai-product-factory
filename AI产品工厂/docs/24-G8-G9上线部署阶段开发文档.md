# G8–G9 上线流程开发文档｜生产化与发布交接

> 日期：2026-08-27
>
> 状态：G8 已验收，G9 上线流程已实现，不执行实际发布
>
> 配套资料：已确认 PRD、G6/G7 验收报告、上线技术适配声明、三份原始手册

## 一、阶段目标

把当前本地可运行的 AI 产品工厂改造成可安全交付的发布候选，并把上线准备、材料检查和发布交接做成可追溯流程。流程在“待人工发布”结束，不连接云平台，不执行实际发布。

本阶段不建设团队、多租户、商业支付、自有域名、RDS、跨地域容灾或多人并行生产。

## 二、用户主链路

```text
打开 HTTPS 地址
→ 输入唯一邀请码登录
→ 新建产品并启动生产
→ Web 与 Worker 在同一实例处理任务
→ 查看真实结果与产物
→ 刷新后恢复同一状态
→ 数据库和产物定期备份到私有 TOS
```

## 三、实现范围

### 3.1 生产运行单元

- Next.js standalone 输出补齐静态资源与 public。
- Next.js Node instrumentation 在服务启动时完成云备份恢复，并只启动一个 Worker 循环。
- Worker 从“导入即运行”改为可显式启动、可幂等停止的运行时接口；本地 `npm run dev` 行为保持不变。
- `FACTORY_DATA_DIR` 线上固定到 `/tmp/ai-product-factory`。

### 3.2 登录

- 新增 `/login` 页面、登录接口和退出接口。
- 邀请码只从服务端 Secret 读取；成功后签发短期 HMAC 会话 Cookie。
- Cookie 使用 HttpOnly、SameSite 和生产环境 Secure。
- 登录页、健康检查和 Next 静态资源以外的页面与 API 全部受保护。
- API 在未登录时返回统一结构，不返回页面 HTML。

### 3.3 数据与文件恢复

- 新增可替换的对象存储端口和 TOS S3 兼容实现。
- 服务启动时，本地数据库缺失才从云端恢复；不得覆盖已经存在的本地数据库。
- 周期性生成 SQLite 一致性快照并上传，保留最近成功时间和错误日志。
- 已登记产物按受控路径同步到私有对象存储；下载仍通过后端鉴权接口。

### 3.4 日志与错误

- 每个请求生成 `trace_id`，写入请求头和响应头。
- 结构化日志只包含时间、级别、事件、路径、状态、耗时、run/project 标识和错误类型。
- 不记录邀请码、Cookie、Key、完整 PRD、完整模型输出或手册原文。
- Sentry 作为线上可选必配项；无 DSN 时明确记录监控待验。

### 3.5 部署文件

- `.vefaasignore` 排除 `.env`、`data/`、缓存、测试报告和 `.vefaas/`。
- 构建脚本创建私有 standalone 部署包，并把静态资源、public、三份手册与校验文件复制到正确位置。
- 三份手册复制目录必须被 Git 忽略；打包后重新校验 SHA256。
- `.env.example` 只列键名和说明，不含真实值。

## 四、环境变量

| 变量 | 生产要求 | 用途 |
| --- | --- | --- |
| `NODE_ENV` | `production` | 生产模式 |
| `ENV` | `prod` | 启用线上安全约束 |
| `FACTORY_AUTH_REQUIRED` | `true` | 强制登录 |
| `AUTH_SECRET` | 必填 Secret | 签名短期会话 |
| `INVITE_CODES` | 第一版只配一个 | 产品负责人邀请码 |
| `FACTORY_DATA_DIR` | `/tmp/ai-product-factory` | SQLite 和受控数据目录 |
| `FACTORY_MANUALS_DIR` | 私有部署包内路径 | 三份原始手册目录 |
| `DEEPSEEK_API_KEY` | 必填 Secret | 真实 Factory Agent |
| `DEEPSEEK_MODEL` | 默认 `deepseek-v4-flash` | 模型选择 |
| `STORAGE_PROVIDER` | 线上为 `s3` | 本地或 TOS |
| `S3_ENDPOINT` | TOS S3 endpoint | 对象存储地址 |
| `S3_REGION` | `cn-beijing` | 存储地域 |
| `S3_BUCKET` | 私有桶 | 数据库和产物备份 |
| `S3_ACCESS_KEY` | 必填 Secret | 最小权限存储凭证 |
| `S3_SECRET_KEY` | 必填 Secret | 最小权限存储凭证 |
| `BACKUP_INTERVAL_MS` | 推荐 300000 | 备份间隔 |
| `SENTRY_DSN` | 正式上线前配置 | 错误告警 |

## 五、自动测试

- 会话签名、过期、篡改、错误邀请码和正确邀请码。
- Proxy 对页面重定向、API 401、公开登录资源放行。
- Worker 启动幂等、停止和本地开发兼容。
- 本地对象存储与 S3 端口契约。
- 数据库不存在时恢复、已存在时不覆盖、快照上传失败不破坏本地数据。
- 私有部署包不包含 `.env`、本地 data、日志和 Git 元数据。
- 三份手册在部署包中逐字节校验通过。
- 原有 70 个测试、Lint、类型检查和生产构建全部继续通过。

## 六、真实验收

### 本地发布候选

1. 用 production build 启动 standalone。
2. 未登录访问首页跳转登录页。
3. 错误邀请码被拒，正确邀请码进入首页。
4. 新建项目，启动一次真实 DeepSeek 生产，结果可查看。
5. 刷新页面状态和产物仍在。
6. 检查 Console、Network、SSE、错误状态和四档宽度。
7. 停止服务，模拟从备份恢复后重新打开历史数据。

### G9 上线流程

1. 真实验收通过后生成上线方案，包含目标环境、配置键名、发布前确认、人工发布步骤和回滚方案。
2. 确认上线方案后，确定性检查产品候选版本、自动检查、真实验收、上线方案和回滚材料。
3. 检查通过后生成手工发布清单，明确列出人工操作和未执行项。
4. 最终确认只把项目状态更新为 `candidate`，并记录 `deploymentStarted: false`。
5. 任何云端登录、资源创建、Secret 写入、Git push、上传、部署、发布和回滚均不在流程内执行。

## 七、完成判定

只有以下条件全部满足，才允许写“发布候选已就绪”：

- 自动检查全部通过；
- 本地 production standalone 闭环通过；
- 真实 DeepSeek 冒烟通过；
- 上线方案、上线检查和手工发布清单均已生成并确认；
- 生产档案记录 `deploymentStarted: false`；
- 项目状态为 `candidate`，不是 `released`；
- 所有页面明确显示“待人工发布”。

本版本在任何情况下都不由产品工厂写“已经上线”。
