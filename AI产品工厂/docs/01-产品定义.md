# AI 产品工厂｜产品定义 V0.1

## 1. 产品定位

AI 产品工厂是一套供产品负责人本人使用的 Web 生产控制台。用户导入 PRD 后，系统通过确定性生产控制器编排 Pi Agent，在 DeepSeek 模型驱动下完成技术适配、分阶段开发、测试验收、产品界面和发布准备。

被生产的产品不要求自身包含 AI。第一版通用性目标覆盖小游戏、AI Agent 应用、内容工具、SaaS、内部工作台、数据工具和 API 产品等常见数字产品；具体生产路线由产品画像决定。

它首先解决的是“如何稳定地把一个真实想法生产成可验收产品”，而不是“如何让 Agent 尽可能自主”。

## 2. 目标用户与核心任务

### 目标用户

- 第一版唯一用户：产品负责人本人。
- 用户懂产品目标，但不应被迫处理大量工程细节。

### 核心任务

```text
导入一个产品 PRD
→ 看见工厂对需求的理解和生产路线
→ 批准关键决策
→ 观察 Agent 按阶段生产
→ 在需要时暂停、补充信息或重试
→ 验收真实产品效果
→ 得到可运行、可测试、可发布的产品版本
```

## 3. 产品目标

第一版必须做到：

1. 每个产品项目有独立工作区和可恢复的生产状态。
2. WebUI 能展示当前阶段、工位、实时事件、工具调用、产物和阻塞原因。
3. 用户可以开始、暂停、继续、取消、重试生产批次。
4. 用户可以在人工闸门批准、拒绝或补充要求。
5. 生产控制器根据工位协议驱动 Pi Agent，而不是让模型自由决定整条生命周期。
6. Agent 能在权限策略内读写项目、执行命令、运行测试和生成文档。
7. 每个阶段必须留下结构化产物和质量证据，中断后可从检查点继续。
8. 以一个真实小游戏完成首条端到端试产。
9. 产品专属要求通过可组合生产蓝图和能力包进入流水线，不污染工厂内核。
10. 新增另一类产品时，不修改生产控制器状态机，只新增或组合相应能力包。

## 4. 第一版明确不做

- 多用户、多租户、团队协作和商业化权限体系。
- 同时并发生产大量产品。
- 无人监管地执行付费、发布、删除或外部发送操作。
- 原生 App、小程序、强监管、高并发和微服务产品的通用生产。
- 让大模型直接成为生产状态的唯一事实来源。
- 第一版就建设云端远程开发沙箱、Agent 市场或模型市场。
- 宣称第一版可以无条件生产原生 App、硬件、强监管或高并发分布式系统；这些需要后续能力包和专门基础设施。

## 5. 核心用户流程

### 5.1 新建产品项目

用户填写项目名称，上传或粘贴 PRD，选择本地工作区，可选填写设计参考、目标终端、模型和成本约束。系统先生成产品画像，再据此编译本项目的生产蓝图。

系统完成资料体检，生成：

- 产品理解摘要；
- 缺失但会影响方向的问题；
- 推荐开发路径；
- 识别出的产品画像和触发的能力包；
- 初版阶段路线图；
- 第一张生产单。

### 5.2 确认后开始生产

用户在“产品范围”人工闸门确认或退回修改。确认后，生产控制器创建生产批次，依次调度工位。

### 5.3 观察和干预

生产运行时，用户可以看到：

- 当前生产阶段与工位；
- Agent 的用户可见说明；
- 工具调用及结果摘要；
- 文件变更和 Git diff；
- 测试、构建、浏览器检查结果；
- Token、耗时和预估模型费用；
- 阻塞原因和下一步。

用户可以暂停、补充说明、批准受控操作、重试失败工位或终止生产批次。

### 5.4 验收与发布

Agent 效果和发布是独立人工闸门。用户必须亲自操作真实闭环并确认效果；所有质量闸门通过后，系统才生成发布候选。创建计费资源或正式部署仍需单独批准。

## 6. WebUI 信息架构

### P0 页面

| 页面 | 主要用途 |
| --- | --- |
| 项目列表 | 新建项目、查看阶段、最近批次和阻塞状态 |
| 新建项目 | 导入 PRD、选择工作区、填写约束 |
| 项目总览 | 查看产品画像、生产蓝图、当前阶段、质量状态和下一步 |
| 生产驾驶舱 | 实时查看事件流、工具调用、变更、成本并进行暂停/继续 |
| 人工闸门 | 查看待确认内容、影响、推荐项并批准/拒绝/补充 |
| 产物中心 | 查看文档、代码变更、测试报告、截图和发布候选 |
| 设置 | 配置 DeepSeek、工作区、执行限制和部署凭证引用 |

### P1 页面

- 历史生产批次对比；
- Prompt 与工位模板管理；
- 模型成本趋势；
- 跨项目复用的产品模板。

## 7. 人工闸门

第一版固定四类人工闸门：

1. **产品范围确认**：确认目标、MVP 范围和开发路线。
2. **重大影响确认**：确认新增费用、外部平台、敏感数据、破坏性操作或显著架构变化。
3. **Agent 效果验收**：确认真实模型或游戏体验是否达到产品标准。
4. **发布确认**：确认创建计费资源或把发布候选部署到线上。

## 8. 成功指标

小游戏真实试产和非游戏蓝图验证共同满足以下条件，通用工厂 MVP 才算成立：

- 从导入 PRD 到生成发布候选，全程由同一个产品项目记录串联。
- 至少经历一次人工闸门、一次自动质量闸门和一次失败后的恢复。
- 刷新 WebUI 或重启 Worker 后，生产批次能够从检查点继续。
- 用户能从 WebUI 判断“现在在做什么、为什么停、下一步是什么”。
- Agent 产生的代码可以真实启动，核心游戏闭环可以在浏览器操作。
- 自动测试、生产构建和浏览器验收均有可查看证据。
- 未经批准，系统没有执行发布、付费或破坏性动作。
- 用一个非游戏产品画像完成蓝图编译测试，证明不会默认生成游戏工位、游戏数据或游戏验收项。

## 9. 当前假设与待小游戏 PRD 验证项

- 第一版采用本地优先部署：WebUI 和 Worker 在用户电脑运行。
- 第一版同一时间只允许一个生产批次执行写操作。
- 代码项目使用 Git；工厂不自动覆盖用户已有未提交修改。
- DeepSeek 是主要模型，但具体模型档位由配置决定，不写死在工位中。
- 小游戏的目标终端、技术栈、资产需求和发布平台收到 PRD 后决定。
