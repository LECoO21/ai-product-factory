# G9 上线流程实现与验收

> 日期：2026-08-27
>
> 状态：已实现并通过全量验收
>
> 边界：只生成发布候选与手工发布清单，不执行实际发布

## 1. 方向变更

原 G9 以“发布到 veFaaS 并验收公网 HTTPS”为目标。2026-08-27 产品负责人明确要求：把上线过程做成产品工厂内的可执行流程，但不做任何实际发布。

因此 G9 的完成边界改为：

```text
真实产品验收
→ 上线方案
→ 上线材料检查
→ 手工发布交接
→ 发布候选
→ 停止
```

## 2. 三个上线工位

### 2.1 上线方案

- 阶段 ID：`release-preparation`。
- 输入：已确认产品、自动检查、真实验收和三份手册。
- 输出：候选版本、目标环境、配置键名、发布前确认、人工发布步骤、回滚方案和未执行项。
- 闸门：产品负责人确认方案后才进入上线检查。

### 2.2 上线检查

- 阶段 ID：`release-readiness`。
- 执行方式：确定性代码，不依赖模型自评。
- 必查证据：产品候选版本、自动检查通过、真实验收确认、上线方案、回滚方案、未执行发布。
- 失败行为：任一证据缺失则停在失败状态，不生成发布交接。
- 闸门：产品负责人确认检查结果后才生成手工发布清单。

### 2.3 待人工发布

- 阶段 ID：`release-handoff`。
- 输出：手工发布清单和明确未执行项。
- 最终确认：项目状态从生产中更新为 `candidate`。
- 事件证据：`gate.approved` 记录 `gate: release_handoff`、`completed: true`、`deploymentStarted: false`、`projectStatus: candidate`。
- 终止条件：不创建下一生产批次，不进入 `released`。

## 3. 硬性不执行项

上线流程不得执行：

- 登录 veFaaS 或任何云平台；
- 创建或修改应用、函数、网关、存储、域名或付费资源；
- 写入正式环境变量或 Secret；
- Git push、上传、部署、发布、回滚或删除；
- 把“发布候选”描述为“已上线”。

## 4. 代码变更

- `ProductionStage` 新增 `release-readiness` 和 `release-handoff`。
- `ProductionController` 把上线方案、检查和交接串成幂等状态流转。
- Worker 新增确定性上线检查和手工发布清单生成。
- 旧 G6 Harness 验证只在生产目标明确包含 Harness 验证时执行；普通产品制作会登记第一版产品 HTML，并继续进入自动检查、真实验收和上线流程。
- 项目只在最终交接确认时更新为 `candidate`。
- WebUI 进度增加“上线方案”、“上线检查”和“待人工发布”。
- 手机和平板使用紧凑阶段标题，避免 8 阶段横向溢出。

## 5. 验收条件

- 三个上线阶段按顺序且每步只创建一次；
- 上线检查缺任一证据时必须失败；
- 上线检查通过后才能生成手工发布清单；
- 最终确认后项目状态为 `candidate`；
- 所有记录中都不得出现已执行发布的事实；
- Lint、类型检查、Vitest、Playwright、生产构建和三份手册校验全部通过。
