# 第一阶段前端开发文档｜生产驾驶舱代表页

> 配套文档：三份原始手册、`docs/07-前端技术适配声明.md`。  
> 阶段状态：页面实现与本地浏览器验收完成；真实 DeepSeek 冒烟待 Key。

## 1. 本阶段目标

产品负责人进入首页后，可以看清工厂当前有多少项目和批次、哪个批次需要处理、工厂如何生产不同产品，以及三份原始手册如何贯穿产品旅程。

## 2. 范围

### 本阶段包含

- 生产驾驶舱首页；
- 真实项目、生产批次、事件数和能力包统计；
- 当前批次状态与运行控制台入口；
- 三手册工程宪章入口；
- 通用生产路线和真实项目卡片；
- 路由加载、空数据、阻塞、错误恢复状态；
- 390px、768px、1280px、1440px 响应式布局。

### 本阶段不包含

- 暂停、steer、继续、abort；
- 产物中心；
- 人工闸门操作界面；
- 登录、多用户权限与正式部署；
- 用 Mock 伪造成功批次或产物。

## 3. 用户流程

1. 打开生产驾驶舱，查看真实工厂概况。
2. 查看当前最需要关注的生产批次和阻塞原因。
3. 进入批次驾驶舱，查看持久化事件。
4. 返回首页，查看生产路线和产品项目。
5. 通过“导入新 PRD”进入已有项目创建流程。

## 5. 接口契约

- 首页 Server Component 通过 `ProductFactory.listProjects()` 和 `ProductionRunStore.listForProject()/events()` 读取服务端数据；浏览器不直接访问 SQLite。
- 批次入口沿用 `/runs/{runId}`；运行事件沿用 `/api/runs/{runId}/events` SSE。
- 页面只解释已存在的受控状态；未知或未实现能力不显示为可操作按钮。

## 6. 实现方案

- 路由：`/` 作为生产驾驶舱，保留 `/projects/new`、`/projects/{id}`、`/runs/{id}`。
- 组件结构：首页保持 Server Component；交互只使用链接和既有 Client Component，减少客户端边界。
- 状态来源：SQLite 与服务端领域模块是事实来源。
- 流式/轮询：首页不重复建立 SSE；进入运行控制台后使用既有 SSE。
- 响应式处理：820px 以下改为单列，生产路线纵向排列；390px 操作按钮占满可用宽度。
- 安全和隐私：不读取或展示 Key；错误页只记录 digest，不向用户显示堆栈。

## 7. 验收标准

- 首页真实显示现有 1 个项目、1 个阻塞批次、4 条事件和 5 个能力包。
- 阻塞批次显示“等待配置”，并显示缺少 `DEEPSEEK_API_KEY`，不能显示成功。
- 点击“查看生产现场”滚动到正确区块；点击批次入口进入真实运行页。
- 390px、768px、1280px、1440px 页面宽度均等于视口宽度，不出现无意横向滚动。
- `npm run manuals:verify`、lint、类型检查、测试、生产构建全部通过。

## 8. 风险与回退

- 风险：当前首页直接读取本地 SQLite，只适合第一版本地单用户控制平面。
- 风险：缺少真实 DeepSeek Key，不能验证 Agent 输出质量和真实延迟。
- 降级：数据库读取失败时显示错误恢复页，不把失败降级成空列表。
- 回退：页面改动集中在首页、样式和显示标签；已有项目与批次路由保持不变。
