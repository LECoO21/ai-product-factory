# 第一阶段前端开发文档｜精简生产控制页

> 迁移状态（2026-09-02）：本文保留为 Pi Agent + DeepSeek 时期前端历史基线；运行时、登录和能力状态以 Codex App Server 迁移文档与当前代码为准。
>
> 配套文档：三份原始手册、`docs/07-前端技术适配声明.md`。  
> 阶段状态：页面、真实确认入口、规划阶段流转和本地浏览器验收已完成。

## 1. 本阶段目标

页面只告诉产品负责人三件事：当前在哪一步、AI 结果是什么、现在需要点哪个按钮。

## 2. 本阶段范围

### 已实现

- 首页：待处理任务、去确认、产品列表、新建产品。
- 产品页：继续当前任务、最近 20 个步骤记录、折叠 PRD。
- 新建页：产品名称、PRD、创建、返回。
- 运行页：当前步骤、AI 结果、确认按钮、默认收起的最近 20 条运行记录。
- 确认流程：“理解产品 → 确定技术方案 → 生成开发计划”。
- 刷新恢复：批次 ID、状态、事件和人工确认都来自 SQLite。
- 响应式：1440px 展示六步进度；390px 只展示“第几步 · 当前步骤”，不产生横向滚动。

### 未实现

- Agent 自动写入产品代码。
- 受控文件工具、Shell、Git 和自动测试工具。
- 暂停、补充指令、继续、终止和用量摘要。
- 自动检查、真实产品验收、发布候选和部署。

## 3. 用户流程

1. 新建产品，填写产品名称和 PRD。
2. 进入产品页，点击“开始分析”。
3. 在运行页查看 AI 对产品的理解。
4. 点击“确认理解，进入技术方案”。
5. 查看技术适配结果，点击“确认方案，生成开发计划”。
6. 进入开发计划工位。

## 4. 状态与接口

| 状态 | 页面显示 | 用户操作 |
| --- | --- | --- |
| `ready` | 等待 AI 开始 | 等待 |
| `running` | AI 正在处理 | 查看结果 |
| `waiting_approval` | 等你确认 | 点击业务含义明确的确认按钮 |
| `blocked` | 等待配置 | 根据错误信息处理 |
| `succeeded` | 这一步已完成 | 查看结果或进入下一步 |
| `failed` | 这一步失败 | 查看运行记录 |

- `POST /api/runs/{id}/approve`：后端检查当前工位和状态，持久化 `gate.approved`，幂等地创建下一工位。
- `GET /api/runs/{id}/events`：SSE 返回持久化运行事件。
- 首页同时识别 `waiting_approval` 和旧数据中未写入 `gate.approved` 的 `succeeded` 规划批次。

## 5. 验收标准

- 用户能在首页一眼看到“去确认”。
- 确认按钮不是假按钮：后端会创建真实下一工位。
- 只有 `agent.completed` 且累计生成不少于 20 个非空白字符时才显示确认按钮；空结果显示“结果为空”和“重新分析”。
- 重复确认只能得到同一个下一工位。
- 页面不显示 Worker、Pi、`SUCCEEDED` 等内部术语。
- 运行记录默认收起，最多渲染 20 条，内部纵向滚动。
- 390px 与 1440px 无横向溢出，手机端主按钮占满可用宽度。
- Console 无应用自身错误。
- `npm run manuals:verify`、lint、类型检查、测试和生产构建全部通过。

## 6. 验证证据

- 确认流转回归测试覆盖两道闸门和重复确认。
- 空 Agent 结果回归测试覆盖“不得确认”和“同工位重试”；Worker 不再为空结果创建人工闸门。
- 失败批次状态映射回归测试覆盖“显示真实错误、停止处理动画、提供重新分析”，不再把未知终态默认显示为处理中。
- Pi Agent 运行时在没有 `text_delta` 时会从 `agent_end` 的最终 assistant 消息恢复正文；已有流式正文时不重复保存。
- 真实浏览器已检查首页、产品页、新建页和运行页。
- 390px 和 1440px 的 `scrollWidth` 都不超过视口宽度。
- 本轮浏览器验收未替用户点击确认，避免未经授权产生真实 DeepSeek 费用；后端确定性流转由自动测试验证。

## 7. 风险与后续

- 当前 WebUI 和 SQLite 面向本地单用户，不是正式多用户产品。
- 技术适配和开发计划可以衔接，但开发计划之后尚无受控代码生产能力。
- 受控工具、检查点、自动质量证据和真实产品试产完成前，不得声称整条生产线已完成。
