## 1. G3 结论

AI 产品工厂自身需要一套受控 Harness，让工厂 Agent 可以读取生产资料、在独立目标产品工作区内行动、运行真实验证、登记产物，并用可追溯证据判断下一步。

这套领域骨架的核心边界是：

- 工厂 Agent 可以在已确认目标和权限内决定“下一项普通操作”；
- 生产控制器是生产状态、阶段和人工闸门的唯一事实来源；
- 工具执行器只执行通过参数校验、路径校验和权限裁决的请求；
- 工厂 Agent 的文字声明、模型停止或等待超时都不能代表任务完成；
- 真实产物和证据存在后，界面才允许出现对应确认入口；
- 费用、破坏性操作、外部发送和 Git 远程推送必须先由产品负责人确认；当前上线流程只生成发布候选和手工清单，不执行发布；
- 三份原始手册保持最高优先级，不能被摘要、派生文档或 Agent 自己的判断替代。
- Codex App Server 是唯一 Factory Agent 运行时；用户的 OpenAI 账户是必需前置，但凭据不属于工厂数据。
- 图片、音频和 3D 产物必须来自已检测的真实工具，不存在工具时不得伪造成功。

本文件描述的是**工厂自身的生产 Harness**。任何目标产品都可以由它生产，不要求目标产品本身包含 AI。只有当某个目标产品本身也是 Agent 产品时，才为该目标产品额外建立一套五要素；不能把工厂的 Harness 强行安装进小游戏、普通网站或数据工具的运行时。

## 2. 领域边界与责任

| 领域对象 | 拥有什么责任 | 明确不拥有 |
| --- | --- | --- |
| 产品负责人 | 确认产品目标、重大影响、阶段结果和最终发布 | 不负责逐次批准普通读写、测试和查看操作 |
| 生产控制器 | 管理生产批次、阶段、暂停、恢复、终止、人工闸门和状态转换 | 不决定阶段内每一次工具调用 |
| 工厂 Agent | 在当前生产单和权限内规划、调用工具、分析观察并提交产物 | 不自行改变阶段，不自行宣布质量通过，不绕过权限 |
| 工具执行器 | 校验并执行单个受控动作，返回结构化结果 | 不理解整个产品目标，不自行扩大路径或权限 |
| 质量闸门 | 根据完成目标和已登记证据给出通过或不通过 | 不接受 Agent 自评或空结果作为证据 |
| 人工闸门 | 保存产品负责人的明确决定及其对应版本 | 不被超时、模型输出或页面动画自动触发 |
| 生产档案 | 保存输入、版本、事件、确认、检查点、证据和产物索引 | 不用聊天记录替代结构化事实 |
| 目标产品工作区 | 隔离某个产品项目的代码、资产和生产结果 | 不允许 Agent 默认访问其他项目或用户私人目录 |

### 2.1 不变量

以下规则在后续组件选型和实现中不能被改变：

1. 一次工具请求必须对应一次结构化工具结果，成功、失败和被拒绝都要记录；
2. 任何有副作用的动作都必须先完成权限裁决，失败时默认关闭而不是默认放行；
3. 生产批次的阶段只能由生产控制器改变；
4. 人工确认必须绑定具体产物版本，产物变化后旧确认不能继续放行；
5. 质量通过必须绑定可查看证据，Agent 回复“完成”不构成证据；
6. 任务、人工确认、工具副作用、检查点和最终产物必须可在进程重启后恢复；
7. 空结果、解析失败、模型失败、超时和仍在处理中时都不能出现确认入口；
8. 权威手册内容不能在上下文压缩中丢失或被摘要替代；
9. 任何目标产品专属概念不得进入工厂通用内核；
10. 未通过 G6 前，不修改新方向的生产代码，也不开始修改首个目标产品代码。

## 3. Harness 五要素总表

| 要素 | 工厂中的含义 | 要回答的问题 | 最低合格条件 |
| --- | --- | --- | --- |
| 工具 | Agent 可请求的原子外部能力 | 为了产生交付物，需要读取、写入、调用、验证或登记什么 | 输入输出有 schema，副作用明确，错误结构统一 |
| 知识 | Agent 做出正确决定时必须访问的权威资料与动态上下文 | 规则来自哪里，版本是什么，冲突时听谁的 | 来源、优先级、版本和加载记录可追溯 |
| 观察 | 行动后可验证结果的真实信号 | 怎样证明动作生效、失败或产生偏差 | 观察可登记为证据，不能只依赖模型描述 |
| 行动 | 工具作用于外部世界的执行形式 | 通过文件、CLI、API、浏览器还是消息完成 | 先裁权、再执行、再观察、再记录 |
| 权限 | 对数据、路径、副作用、费用和外部系统的边界 | 什么自动允许，什么必须确认，什么永远禁止 | 默认拒绝、风险分级、人工闸门和审计齐全 |

## 4. 工具：工厂 Agent 需要哪些外部能力

这里列的是**领域能力**，不是 G4 的技术组件选型。后续可以用不同实现承载，但不能丢失这些能力和约束。

| 工具能力 | 主要输入 | 主要输出 | 副作用 | 默认权限 |
| --- | --- | --- | --- | --- |
| 权威资料读取 | 产品流程 ID、手册标识和版本 | 本次流程的完整原文快照、哈希、加载记录 | 无 | 新产品流程开始时自动允许一次；流程内复用；完成或终止后释放且不再读取 |
| Codex 账户与 Turn | 登录命令、项目/Thread、批次/Turn | 脱敏账户状态、通知、结构化终态 | 可启动登录或 Agent 执行 | 必须由 Worker 经 App Server 执行 |
| 多媒体生产 | 素材类型、规格、已配置工具 | 图片、音频或 3D Artifact 与能力状态 | 可调用外部工具或产生费用 | 未配置时阻塞；费用与外部写入按风险裁决 |
| PRD 与文档导入 | 用户文字或受支持文件 | 原文件索引、提取文本、解析错误 | 登记输入文件与派生文本 | 自动允许；不支持格式明确失败 |
| 工作区查看与搜索 | 项目 ID、受控相对路径、查询条件 | 文件列表、片段、元数据 | 无 | 仅目标产品工作区内自动允许 |
| 工作区文件变更 | 受控相对路径、补丁、新内容 | 变更结果、文件哈希、差异摘要 | 创建或修改文件 | G6 通过且存在有效生产单后自动允许 |
| Git 状态与差异查看 | 目标产品工作区 | 状态、diff、分支和提交信息 | 无 | 自动允许，只读 |
| Git 本地版本记录 | 已验证变更、提交说明 | 本地提交 ID | 写入本地 Git 历史 | 有效生产单内允许；不得覆盖用户历史 |
| 受控命令执行 | 命令、参数、工作目录、超时 | 退出码、标准输出、标准错误、耗时 | 可能修改文件或启动进程 | 通过命令和路径策略后允许 |
| 依赖安装 | 已确认技术方案中的包与版本 | 锁文件变化、安装结果、安全提示 | 修改依赖和锁文件、访问软件源 | 已确认阶段内允许；新增付费服务另行确认 |
| 自动测试与构建 | 测试范围、构建目标 | 退出码、报告、覆盖关系、产物路径 | 生成缓存、报告和构建产物 | 自动允许 |
| 浏览器真实验收 | 本地或已授权地址、操作步骤、目标尺寸 | 页面状态、Console、Network、截图和操作结果 | 可能创建测试数据 | 本地与测试环境允许；外部提交按风险裁决 |
| 数据与任务记录 | 生产批次、任务、事件、检查点 | 持久状态、序号和恢复位置 | 写入工厂数据库 | 生产控制器与受控记录接口允许 |
| 产物登记 | 文件、类型、来源、哈希、证据关联 | 产物 ID、版本和可查看入口 | 写入档案和索引 | 自动允许；原文件不得被派生物覆盖 |
| 人工闸门请求 | 闸门类型、产物版本、影响说明 | 待确认记录或明确决定 | 暂停后续阶段 | 允许请求；只有产品负责人能批准 |
| 质量证据提交 | 完成目标、观察结果、证据引用 | 通过、不通过或证据不足 | 影响质量闸门判断 | 允许提交；不能由 Agent 自评直接放行 |
| 外部系统调用 | 已确认的 API、账户、数据范围 | 结构化响应与外部回执 | 可能写入外部系统或产生费用 | 默认关闭；按目标产品 PRD 单独授权 |
| Git 远程推送与发布 | 已确认版本、目标远程或环境 | 远程提交、发布记录、访问地址 | 对外可见、可能计费或难以撤销 | 每次重大动作前必须人工确认 |

### 4.1 工具契约的共同字段

每个实际工具在 G5/G6 中至少定义：

- 工具名称和业务用途；
- 输入 schema 与字段限制；
- 输出 schema 与统一错误结构；
- 允许的工作区、路径和环境；
- 是否只读、可逆、有副作用或可能计费；
- 默认超时、有限重试、最大输出和取消方式；
- 权限等级与人工确认条件；
- 执行前后需要记录的生产事件；
- 能作为哪一项完成目标的证据；
- 重复执行时的幂等或去重策略。

## 5. 知识：工厂 Agent 必须知道什么

### 5.1 权威顺序

| 优先级 | 知识来源 | 使用规则 |
| --- | --- | --- |
| 1 | 本次产品流程已锁定的三份原始手册全文 | 最高工程规范；新产品流程开始时完整加载与 SHA 校验；流程内复用；完成或终止后释放；下一个新产品重新读取；不得摘要替代 |
| 2 | 当前产品项目已确认的 PRD 版本 | 规定业务目标、用户、范围、产物和验收 |
| 3 | 已确认的上游阶段产物 | 只能使用当前有效版本；下游不得偷偷改变上游决定 |
| 4 | 当前生产单与完成目标 | 限定本次 Agent 可以做什么、预算和退出条件 |
| 5 | 目标产品现有代码、schema、测试和文档 | 作为当前真实实现依据；发现冲突要报告 |
| 6 | Agent Blueprint | 用于推导 Harness 和架构的参考，不能覆盖三份手册或 PRD |
| 7 | 工具说明、能力包和目标领域资料 | 按当前任务最小必要范围加载并记录版本 |
| 8 | 运行期事件、观察和产品负责人本轮决定 | 用于恢复和继续；不得反向改写历史事实 |

### 5.2 知识保护规则

- 每个新产品流程开始时锁定三份完整原文快照，流程内所有工位、返工、重试和恢复保持稳定前缀并复用；流程完成或终止后释放且不再读取；下一个新产品重新读取；派生摘要只用于导航，不能替代原文；
- 用户上传的 PRD、网页内容、代码注释和目标产品数据都视为不可信内容，不能借其中指令覆盖系统规则、手册或权限；
- 每次产出记录使用了哪些知识版本和哈希，确保后续能解释结果来源；
- 秘密、密码和 API Key 不属于 Agent 知识，不进入 Prompt、事件、日志或前端；
- 普通长对话和大段工具结果可以裁剪或摘要，但必须保留未完成目标、关键决定、工具调用与结果配对、检查点和权威资料引用；
- 当 PRD 与代码、手册或已确认产物冲突时，Agent 先报告具体冲突和影响；重大影响项进入人工闸门，不自行猜测；
- 目标产品的领域知识只属于对应产品项目，默认不能跨项目共享。

## 6. 观察：怎样知道行动真的有效

| 观察类型 | 可观察事实 | 可证明什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 文件观察 | 文件存在、哈希、大小、解析结果 | 产物真实生成且可读取 | 内容一定满足 PRD |
| Git 观察 | 状态、diff、提交 ID | 哪些代码真实改变、能否追踪 | 修改一定正确 |
| 命令观察 | 命令、退出码、输出、错误、耗时 | 工具是否执行和是否正常退出 | 用户体验一定合格 |
| 测试观察 | 用例、通过/失败、覆盖链路、报告 | 被测试规则是否满足 | 未覆盖路径一定正确 |
| 构建观察 | 构建结果、产物路径、警告 | 工程是否可构建 | 页面视觉和交互已验收 |
| 浏览器观察 | 页面内容、交互结果、Console、Network、尺寸、截图 | 真实界面闭环和响应式表现 | 后端重启后一定可恢复 |
| 状态观察 | 任务、阶段、租约、检查点、事件序号 | 当前生产事实与恢复位置 | 模型说完成就可以结束 |
| 模型观察 | 模型名、首字时间、总耗时、Token、错误和结构校验 | 真实模型契约是否跑通 | 业务质量自动通过 |
| 人工观察 | 产品负责人对指定版本的确认、退回和说明 | 产品效果与重大决定是否被接受 | 其他版本自动被接受 |
| 外部回执 | 远程提交 ID、发布状态、访问地址、响应 | 外部动作是否被目标系统接收 | 最终线上产品全部健康 |

### 6.1 证据准入规则

一项观察只有同时满足以下条件，才能登记为质量证据：

1. 关联明确的产品项目、生产批次、任务和完成目标；
2. 来源可识别，时间和执行条件可追溯；
3. 结果不是空值，也不是仍在运行的中间状态；
4. 有结构化成功或失败结论；
5. 失败结果如实保留，不能删除或改写成成功；
6. 产物证据可以从 WebUI 打开、预览或定位；
7. 人工确认绑定产物版本，版本变化后重新确认；
8. 需要真实模型或真实浏览器的验收，不能由 mock 冒充。

## 7. 行动：Agent 通过什么形式影响外部世界

### 7.1 行动形式

| 行动形式 | 适用范围 | 约束 |
| --- | --- | --- |
| 文件补丁 | 文档、源代码、配置模板、测试 | 使用受控相对路径；保留用户已有修改；禁止越界写入 |
| CLI | 搜索、Git、本地开发、测试、构建 | 命令和参数结构化；工作目录固定；超时；危险模式拦截 |
| 内部 API | 项目、任务、事件、产物、闸门和查询 | 请求响应 schema；幂等；统一错误；权限由服务端执行 |
| 浏览器 UI | 真实交互、视觉和响应式验收 | 使用测试身份和数据；记录 Console、Network 和截图 |
| 模型调用 | 规划、分析和生成 | 经 AgentRuntime；模型配置化；超时和有限重试；输出校验 |
| 外部 API 或消息 | 目标产品确实需要的系统集成 | 默认禁用；数据范围、费用和副作用确认后开放 |
| 发布动作 | Git 远程、部署平台、应用商店或其他公开环境 | 独立人工闸门；发布后验证；保存回执和回退路径 |

### 7.2 单次行动生命周期

```text
工厂 Agent 提出工具请求
→ 校验输入 schema
→ 校验项目、路径、命令、数据和预算边界
→ 权限裁决：允许 / 需要人工确认 / 拒绝
→ 执行一次原子动作
→ 收集结构化观察
→ 写入工具结果、生产事件和副作用记录
→ 更新任务与检查点
→ Goal Gate 根据证据决定继续、完成、失败或交还用户
```

任何一步失败都必须进入明确失败或等待状态。系统不能因为等待时间长，就假装已经得到结果并弹出确认。

## 8. 权限：什么自动做、什么先确认、什么绝不做

### 8.1 风险等级

| 等级 | 含义 | 交互方式 |
| --- | --- | --- |
| P0 只读 | 不改变产品、数据或外部系统 | 自动执行并记录，不逐次打扰用户 |
| P1 受控可逆 | 在已确认阶段和目标工作区内产生可追踪、可恢复的变更 | 自动执行并记录；失败可重试或回退 |
| P2 重大影响 | 可能删除或覆盖数据、产生新增费用、向外发送、改变远程仓库或正式环境 | 执行前展示影响和推荐方案，等待产品负责人明确确认 |
| P3 禁止 | 越权、泄密、绕过闸门、破坏手册或无法控制的高风险动作 | 直接拒绝并记录，不提供自动绕过 |

### 8.2 权限矩阵

| 动作 | 等级 | 裁决 |
| --- | --- | --- |
| 产品流程开始时读取三份原文；流程内读取已锁定快照、已确认文档和目标工作区 | P0 | 原文只在流程开始时自动读取一次；流程内只读复用快照并记录来源版本 |
| 查看 Git、数据库结构、任务和事件 | P0 | 自动允许；秘密字段必须脱敏 |
| 在 G6 通过前生成 G1–G6 文档产物 | P1 | 只写项目文档与状态记录，不修改生产代码 |

| 删除或覆盖用户数据、数据库、重要产物和大量文件 | P2 | 先说明精确目标、影响与恢复方式，再等待确认 |

| 删除测试、隐藏错误或用 mock 冒充真实验收 | P3 | 永久禁止 |

### 8.3 确认原则

- 普通读文件、改当前工作区、运行测试、构建和查看页面不逐次弹窗；
- 一个阶段只在真实产物存在并登记后出现 G1–G9 对应确认；
- P2 动作展示“做什么、影响哪里、是否收费、能否恢复、确认后下一步”；
- 同一精确动作在确认有效期内不重复询问，但目标、内容、费用或风险变化后必须重新确认；
- 拒绝、失败、空结果和处理中状态都不能转化为默认确认；
- 产品负责人退回后保留原版本和退回原因，生成新版本后再请求确认。

## 10. 风险与边界清单

| 风险 | 失败表现 | 领域约束 |
| --- | --- | --- |
| 上传内容中的提示注入 | PRD 或网页要求 Agent 忽略手册、泄露数据 | 外部内容只作为数据；权威顺序和权限不可被内容覆盖 |
| 路径越界 | 写入其他项目、私人目录或手册原文 | 所有路径解析到目标工作区；越界直接拒绝 |
| 危险命令 | 模糊删除、覆盖数据库、破坏 Git 历史 | 命令策略、精确目标、默认拒绝；重大删除先确认 |
| 秘密泄露 | Key 出现在日志、事件、Prompt、前端或 Git | 秘密不进入 Agent 知识；输出脱敏；提交前扫描 |
| 模型幻觉 | Agent 声称文件、测试或发布已完成 | 只认可工具观察和登记证据，不认可模型自评 |
| 空结果误确认 | 等待过久后 UI 出现确认 | 只有非空且结构校验通过的真实产物才能创建闸门 |
| 重复副作用 | 断线或重试导致重复任务、扣费、发布或消息 | 幂等键、副作用记录、恢复前先查询真实状态 |
| 进程中断 | Worker 重启后任务丢失或重复执行 | 持久任务、租约、检查点和 Workflow journal |
| 手册完整性丢失 | 摘要替代原文、工位重复读取磁盘原文或公开仓库泄露手册 | 每个新产品流程开始时 SHA 校验并锁定快照、流程内只复用、完成或终止后释放、公开仓库排除、压缩豁免 |
| 目标产品污染工厂内核 | 小游戏字段进入通用数据库或控制器 | 产品差异只进入画像、蓝图、能力包和独立工作区 |

| 长上下文成本过高 | 三份手册导致响应慢、用量上升 | 每个新产品流程只完整读取并锁定一次，流程内复用，完成或终止后释放，下一个新产品重新读取；不压缩手册 |

## 11. 关键领域场景

### 场景 A：普通生产不中断用户

工厂 Agent 在已确认生产单内读取代码、修改目标工作区、运行测试和浏览器验收。这些 P0/P1 动作自动执行并记录；用户只在阶段真实产物完成后收到一次清晰确认。

### 场景 B：没有结果就没有确认

模型超时、返回空文本或文档解析失败时，生产批次进入失败或可重试状态，界面展示原因和恢复方式。系统不创建人工闸门，也不因为等待时间达到某个阈值就显示确认按钮。

### 场景 C：刷新或 Worker 重启后恢复

生产控制器从持久任务、事件序号、检查点和副作用记录恢复。恢复前先查询上一个动作是否已经生效，避免重复修改、重复调用模型或重复发布。

### 场景 D：需求发生重大变化

产品负责人修改已确认 PRD 的目标、终端、外部系统、费用或交付范围。系统先做影响分析，使受影响的技术适配、领域骨架和后续确认失效，再从最早受影响闸门生成新版本；历史版本保留。

### 场景 E：生产非 Agent 产品

目标产品是小游戏、普通网站或数据工具时，工厂 Harness 仍负责生产，但目标产品架构不自动加入模型、Memory、MCP、Agent Teams 或其他 Agent 运行能力。目标产品只获得 PRD 真正需要的能力。

### 场景 F：准备推送或发布

工厂完成本地验证后，可以生成发布方案和候选版本，但 Git push、创建公开仓库、部署、域名切换和对外发送都停在 P2 人工闸门。产品负责人看到目标、费用、影响和回退方式并明确确认后才执行。
