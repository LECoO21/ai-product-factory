## 高优先级问题处理

| 审查项 | 实施内容与证据入口 |
| --- | --- |
| R1 停止被反馈阻塞 | 独立控制桥分离读取游标与待交付命令，停止优先；仅临时未激活允许有限重试，RPC 有超时；永久拒绝/结束均写回执，恢复不重放已回执指令。见 `run-control.test.ts`、聊天组件测试。 |
| R2 错误产品被检查放行 | 静态检查之外运行真实 Chromium，加载脚本并抽查最多 12 个控件；捕获脚本错误和可观察变化。全新无凭据上下文、opaque-origin CSP sandbox、离线与请求阻断，不连接工厂 API。浏览器缺失、超时、无交互证据或需要独立后端均不放行。见 `product-quality.test.ts`。 |
| R3 检查失败不能返工 | 失败检查结果可在聊天框提交修改，事务化创建唯一 implementation 返工批次，复用前版结果/失败信息；保留明确的“仅重新检查”，失败不能确认。见工作流、组件和 E2E 测试。 |
| R4 生成附件同源执行 | 通用附件改为下载并附加禁止脚本的 CSP sandbox；基础 HTML 预览使用 allow-scripts 但不授予 allow-same-origin。真实浏览器验证交互仍可用、存储和工厂 API 不可访问。 |
| R5 写接口缺少统一来源保护 | Proxy 对全部 API 写入统一校验 Origin/Host，无登录也生效；支持 Next 的回环地址规范化及显式可信代理来源，不盲信 forwarded headers；开发启动默认绑定回环地址。见来源测试、Proxy 测试及异源 POST 的 E2E 测试。 |
| R6 引擎与记录不一致 | 普通阶段、Harness driver、steer/abort、关闭和能力读取统一接入现有 Codex App Server Adapter；Worker 不再实例化或调用 DeepSeek。沿用现有协议测试，不改为文字冒充执行。 |

同时修复相关 R12（127.0.0.1 删除误拦）及 R13（已删除产品附件旧链接仍可读）。未扩展至 R8/R9 重复创建、R10 完整历史入口、R11 后续阶段首页提醒、R14 全量快照性能等中优先级工作；DeepSeek 遗留实现不再是生产执行路径，也未作为本轮继续维护对象。

## 技术适配与安全边界

- 原有三手册全文、完整性清单及产品快照机制保持不变；本轮仅调整视觉及已确认流程的实现缺陷，不把工程说明当作原文替代品。
- 旧检查仅凭静态模式就放行，无法提供真实交互证据；本轮用真实但受限的浏览器冒烟替代。它不等于完整 PRD、全部交互、多端或独立后端验收。后端型产品需要后续隔离部署测试能力，不能调用工厂同名 API 伪造成功。
- Worker 新增明确的生产依赖 `playwright`；默认使用本机 Chrome，不自动下载浏览器，也不放宽沙箱以绕过验证失败。
- Codex 官方网站读取受限时，已改从 [OpenAI 官方仓库 App Server 文档](https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md) 核对 `turn/steer`、`turn/interrupt` 及终态事件。沿用现有受限权限与适配器，不引入未核实协议字段。
- Web 免登录不等于模型无需本机 Codex 认证。没有配置的真实图片、音频、3D 能力仍须如实阻塞。本轮不发起账户登录、不调用付费模型、不实际发布。
