# AI 产品工厂｜三份手册执行宪章

> 生效范围：AI 产品工厂的产品分析、开发、前端、测试、部署和交付全过程。

## 1. 唯一权威原文（内部资料）

三份手册按产品旅程顺序组成一套完整规范：

1. 通用技术栈手册：从 PRD 到核心链路与 MVP 验收。
2. 通用前端技术栈手册：从已验证核心链路到正式 Web 前端。
3. 上线部署手册：从前后端验收通过到正式上线。

三份原始文件只保留在内部工作区，不随公开仓库分发。它们是唯一权威全文；本文件和其他项目文档只负责建立索引、适配记录与验证证据，不复述原文，也不以摘要替代原文。

## 3. 项目文档的地位

- `README.md`：项目入口、运行方式和当前验证状态。
- `CONTEXT.md`：项目领域语言。
- `docs/01-06`：当前产品定义、架构、工位协议、计划和适配框架。
- 《技术适配声明》和阶段开发文档：记录本项目如何采用、暂缓或偏离手册默认方案。

这些文件是执行记录，不是手册副本。任何项目结论都应能追溯到原始手册、已确认 PRD或产品负责人本轮明确指令。

## 4. 产品流程内的加载与闸门

每个新产品流程开始时依次执行：三份原文逐字节完整性校验 → 按固定顺序完整读取 → 锁定本次流程的未压缩快照与哈希记录。同一产品流程的 G1–G9 及返工、恢复和重试只复用这份快照，不在每个工位重读磁盘原文。产品流程完成或终止后释放快照且不再读取三份原始手册；下一个新产品流程必须重新校验、完整读取并锁定它自己的快照。

流程内各阶段依次经过：使用已锁定手册快照 → 生成适配产物 → 产品负责人确认 → 当前阶段实现 → 双层测试/真实浏览器验收 → 追踪记录。真实 Codex Turn 或真实素材工具不可用时，对应能力必须明确保持“待验”或“未配置”，不能用 Mock、确定性规则或假素材替代。
