- 本阶段业务目标：完成一个可用于确认整体方向的“生产驾驶舱”代表页面，让用户一眼看到项目、生产阶段、Agent 状态、质量闸门和三手册合规状态。

## 3. 技术选择

- 框架与版本：延续现有 Next.js 16.3.1 + React 19 + TypeScript，不重建平行前端。
- 页面产物：在现有 Web 应用中生成浏览器可访问、最终渲染为 HTML 的代表页面；不另建一套与真实应用脱节的 Mock 前端。
- 样式与组件策略：延续现有语义 CSS 变量和轻量组件；本阶段不引入新组件库。
- 数据请求与状态策略：服务端状态以 SQLite/API 为事实来源；只把页面标签等临时交互留在客户端。
- 流式通信策略：沿用现有 SSE 运行事件流；代表页面不伪造真实生产成功。
- 表单方案：本代表页面优先复用已有创建项目与启动批次入口，不新增复杂表单库。
- 测试方案：Lint、TypeScript、Vitest、生产构建和真实浏览器桌面/390px 检查；真实 DeepSeek 冒烟在配置 Key 后完成。
- 部署环境：当前本地运行；正式上线阶段严格进入《上线部署手册》的 veFaaS 流程。

## 4. Agent 状态

- 后端状态 → 前端统一状态映射：现有 `ready`、`running`、`succeeded`、`failed`、`blocked` 分别表达已受理、执行中、成功、失败和等待配置；后续按手册补齐排队、流式、等待用户、部分成功、取消、断线和过期状态。
- 等待用户确认方式：由确定性生产控制器创建人工闸门，页面明确展示原因、可选项、影响和下一步。
- 取消、重试、断线恢复方式：本阶段只展示真实可用能力；暂停、steer、继续和 abort 尚未完成时不提供误导按钮。
- 任务 ID 和恢复入口：生产批次 ID 保存在 URL；刷新后从 SQLite 重新读取状态和事件。

## 5. 页面与产物

- 核心页面：生产驾驶舱代表页。
- 核心业务闭环：查看真实项目 → 查看生产蓝图/批次状态 → 进入运行控制台 → 查看质量或人工闸门 → 刷新恢复。
- 产物类型和预览方式：本阶段展示生产档案、事件和闸门；后续统一支持文本、图片、视频、音频、文件和 JSON 产物。
- 响应式目标：390px、768px、1280px、1440px；无意横向滚动为零。

## 6. 偏离本手册的地方

- 默认后端基线偏离：工厂控制平面继续使用现有 Node.js/TypeScript 模块化单体，而不是新建 Python/FastAPI；原因是现有系统已稳定运行，手册明确要求已有项目延续合理架构。影响是当前没有 FastAPI/OpenAPI，但接口、校验、持久化和测试底线保持不变。
- Tailwind 使用方式偏离：现有界面以 CSS 语义变量和自建样式为主，仅保留 Tailwind 构建入口；本阶段延续现状，避免为形式统一重构。
- 真实模型冒烟暂缓：未配置 `DEEPSEEK_API_KEY`；不影响页面和阻塞恢复开发，但阻塞 Agent 效果最终验收。
