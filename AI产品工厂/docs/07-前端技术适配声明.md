- 本阶段业务目标：把现有 WebUI 收缩为可直接操作的生产控制页，只保留当前步骤、AI 结果和真实确认入口。

## 3. 技术选择

- 框架与版本：延续现有 Next.js 16.3.1 + React 19 + TypeScript，不重建平行前端。
- 页面产物：在现有 Web 应用中生成浏览器可访问、最终渲染为 HTML 的代表页面；不另建一套与真实应用脱节的 Mock 前端。
- 样式与组件策略：延续现有语义 CSS 变量和轻量组件；本阶段不引入新组件库。
- 视觉方向：保留 Naxe 原创品牌；按真实浏览器取值采用小云雀式中性灰工作台、23px 轻标题、920×164px 输入器、轻量列表和克制 hover，具体执行见 `docs/09-视觉设计规范-Naxe.md`。
- 工作台架构：参考小云雀已登录页面的可收起导航、中央对话输入器、紧凑 Tab、历史恢复和轻动效，映射为 Naxe 的需求/PRD 输入、最近产品和生产批次；不复制内容广场、积分和促销，具体执行见 `docs/10-小云雀式工作台架构-Naxe.md`。
- 品牌与资产边界：使用原创 `Naxe` 名称和像素 `N` SVG 标志；未下载、复制或分发 Pilcrow 的名称、乌鸦 Logo、商业字体、文案、图片或其他受保护资产。
- 数据请求与状态策略：服务端状态以 SQLite/API 为事实来源；前端请求、超时、Zod 校验和 `AppError` 已集中管理，只把提交中和局部展开等临时交互留在客户端。
- 流式通信策略：SSE 已集中管理，按 sequence 去重；断线后先查询后端真实状态，活动态有限退避重连，终态停止。
- 表单方案：本代表页面优先复用已有创建项目与启动批次入口，不新增复杂表单库。
- 测试方案：Lint、TypeScript、Vitest、React Testing Library、Playwright、生产构建和真实浏览器 390/768/1280/1440px 检查；真实 DeepSeek 结果复用 G6 成功批次验收，不新增模型费用。
- 部署环境：当前本地运行；正式上线阶段严格进入《上线部署手册》的 veFaaS 流程。

## 4. Agent 状态

- 后端状态 → 前端统一状态映射：已集中映射为 `idle / submitting / queued / running / streaming / waiting_user / succeeded / failed / cancelled / disconnected / stale`；未知状态不猜测成功。
- 等待用户确认方式：由确定性生产控制器持久化闸门和创建下一工位；页面只展示当前结果和业务含义明确的确认按钮。
- 取消、重试、断线恢复方式：重试、调整和停止只在后端真实允许时展示；断线先读取后端事实，连接恢复后自动回到真实状态。
- 任务 ID 和恢复入口：生产批次 ID 保存在 URL；刷新后从 SQLite 重新读取状态和事件。

## 5. 页面与产物

- 核心页面：首页、产品页、新建页和运行确认页。
- 核心业务闭环：输入需求并发送 → 自动开始分析 → 查看 AI 结果 → 直接确认进入下一阶段，或补充回答/修改意见后重新生成当前阶段结果。
- 产物类型和预览方式：本阶段展示生产档案、事件和闸门；后续统一支持文本、图片、视频、音频、文件和 JSON 产物。
- 响应式目标：390px、768px、1280px、1440px；无意横向滚动为零。

## 6. 偏离本手册的地方

- 默认后端基线偏离：工厂控制平面继续使用现有 Node.js/TypeScript 模块化单体，而不是新建 Python/FastAPI；原因是现有系统已稳定运行，手册明确要求已有项目延续合理架构。影响是当前没有 FastAPI/OpenAPI，但接口、校验、持久化和测试底线保持不变。
- Tailwind 使用方式偏离：现有界面以 CSS 语义变量和自建样式为主，仅保留 Tailwind 构建入口；本阶段延续现状，避免为形式统一重构。
