## 1. 产品形态判断

### 1.1 产品类型与核心任务

AI 产品工厂是一个本地优先、单用户、长任务、分阶段确认、动态工具调用的 Agent 产品。产品负责人从一句需求、详细描述或已有 PRD 开始，逐步确认标准 PRD、技术适配、领域骨架、组件选型、产品架构和阶段计划，再由 Factory Agent 在受控工作区生产真实数字产品。

### 1.2 核心交互

- 多轮对话；
- 分阶段生成和确认；
- 长任务异步运行；
- 动态工具调用；
- 产物预览与真实产品验收；
- 暂停、继续、重试、终止和检查点恢复。

### 1.3 开发路径

**采用纵向切片。**

原因：人工确认、运行状态、错误恢复和产物查看本身就是核心产品能力。只做后端再补界面，无法验证“结果生成后才能确认”“刷新后回到待处理位置”“失败时不显示处理中”等关键体验。

纵向切片不等于继续打磨大规模视觉。每个阶段只实现能够验证当前核心闭环的最小界面，并延续现有对话工作台，不创建平行临时页面。

### 1.4 当前阶段范围

1. G3 Harness 五要素领域建模；

## 6. 偏离或暂缓的默认方案

### 6.1 后端语言与框架

- **手册默认**：新建 Agent MVP 使用 Python 3.11 + FastAPI。
- **本项目采用**：Node.js 22 + TypeScript；Web API 继续使用 Next.js Route Handlers，长任务由独立 Node.js Worker 执行。
- **原因**：这是已有、已运行且已经接通 Pi Agent、DeepSeek、SQLite 和 SSE 的项目；Pi Agent 依赖本身是 Node.js 包。迁移到 Python 会增加双语言边界、重写成本和数据兼容风险，却不增加当前产品价值。
- **影响**：Pydantic、pytest、SQLAlchemy 和 Alembic 使用 TypeScript 生态的等价约束替代；必须保持同等输入输出校验、迁移、测试和错误边界。
- **重新评估**：只有目标能力依赖成熟度明显更高的 Python 生态，且通过独立服务边界带来的价值大于维护成本时再评估；不整体迁移现有系统。

### 6.2 数据校验与测试

- **手册默认**：Pydantic + pytest。
- **本项目采用**：Zod + TypeScript 类型 + Vitest；浏览器闭环使用 Playwright。
- **原因**：与现有 TypeScript 代码一致，已经覆盖共享 schema 和状态测试。
- **影响**：模型结构化输出、API、任务、事件、Workflow journal 和工具参数必须全部通过运行时 schema 校验，不能只依赖 TypeScript 编译类型。
- **重新评估**：不需要为了名称一致迁移；若新增独立 Python 模块，该模块内部按手册使用 Pydantic 和 pytest。

### 6.3 关系数据库迁移方式

- **手册默认**：关系型数据库默认配套 SQLAlchemy + Alembic。
- **本项目采用**：继续使用 `better-sqlite3`，补充显式编号、事务化、可回滚或可恢复的 schema migration，不在当前阶段引入 ORM。
- **原因**：现有数据访问集中在 `packages/records`，查询简单，直接 SQL 边界清晰；为形式统一更换 ORM 会扩大改动面。
- **影响**：迁移系统、旧数据兼容、损坏处理和迁移测试成为强制交付项。
- **重新评估**：多实体查询和迁移复杂度显著增加，或迁移 PostgreSQL 时，评估 TypeScript ORM / migration 工具并单独提交迁移方案。

### 6.4 API 前缀

- **手册默认**：新建公开 API 使用 `/api/v1`；内部 MVP 可使用集中定义的 `/api`。
- **本项目采用**：保留现有内部 `/api` 路由，不做无价值批量改名。
- **原因**：当前只供本地 WebUI 使用，既有调用已经运行。
- **影响**：在公开第三方 API 或发生不兼容协议变化前，必须设计 `/api/v1` 或等价版本策略。
- **重新评估**：首次提供外部调用方或公开部署时。

### 6.5 正式前端介入时机

- **手册默认**：核心能力验证后再做正式前端；人工确认属于核心交互时采用纵向切片。
- **本项目采用**：保留现有对话式 WebUI 作为纵向切片和未来正式前端基础，但暂停与核心链路无关的视觉扩展。
- **原因**：逐步确认、状态恢复和产物查看无法脱离界面验收。
- **影响**：每阶段可以增加最小真实交互；完整视觉、无障碍和全状态矩阵在核心 Harness 通过后按照前端手册验收。
- **重新评估**：不需要另建临时 HTML 验收页；现有 WebUI 继续承担该职责。

## 9. 上下文与手册适配

### 9.1 权威顺序

1. 当前阶段需要的原始手册全文；
2. 已确认 PRD 版本；
3. 已确认的上游产物；
4. 当前生产单、完成目标、工具和预算；
5. 工作区最小必要上下文。

### 9.2 性能处理

- 三份手册原文不压缩、不改写；
- 按阶段完整加载对应手册，跨阶段任务加载三份；
- 稳定原文放在可缓存的固定前缀，不把变化 PRD 放在原文之前破坏前缀缓存；
- 普通对话和工具结果可以转存、裁剪或摘要；权威手册不能用摘要替代；
- 记录首字时间、总耗时、输入输出 Token 和缓存命中；
- 模型空结果进入失败并允许同工位重试，不能进入确认闸门。

## 10. 数据、API 与状态结论

### 10.1 数据

- 继续使用 SQLite 保存项目、原始输入索引、标准 PRD 版本、确认、生产批次、任务、事件、Workflow journal、检查点、用量和产物元数据；
- PRD 原文件、报告、截图和构建包保存到受控本地目录；
- 文件记录必须包含受控路径、原始名称、内容类型、大小、哈希、状态、上传时间和项目归属；
- schema 变化必须迁移现有 1.1MB 本地数据库，不得删除重建。

### 10.2 API

- 保留集中定义的内部 `/api`；
- 长任务使用“提交任务 + 持久状态 + SSE 观察 + 查询最终快照”；
- API 必须定义 Zod 请求、响应和统一错误结构；
- SSE 必须以 done 或 error 结束，断线后通过 run ID 和事件序号恢复；
- 前端不得直接读取 SQLite 或秘密载体。

### 10.3 状态

- PRD G1–G9 作为持久化阶段闸门；
- 固定阶段由生产控制器和 Workflow Runtime 管理；
- 阶段内工具动作由 Factory Agent 在边界内决定；
- 模型停止不等于完成，Goal Gate 只根据已登记证据放行；
- 需求重大变化先做影响分析，再使相关下游版本和确认失效。

## 11. 测试与真实验收计划

### 11.1 第一层：自动化测试

- PRD 输入解析和原文保留；
- 标准 PRD schema、缺失项和冲突标记；
- G1–G9 顺序、退回、幂等和版本失效；
- 工具参数、权限、路径逃逸和高风险拦截；
- Task DAG、Workflow journal、后台通知和恢复；
- SSE chunk / done / error 契约和断线续读；
- 空结果、模型错误、超时、限流和重试；
- SQLite migration、旧数据兼容和损坏处理。

### 11.2 第二层：真实 DeepSeek 冒烟

每种不同模型契约至少完成一条真实链路：

- 一句话需求 → 标准 PRD → 持久化 → 用户可查看；
- 已确认 PRD → 技术适配声明 → 持久化 → 用户可查看；
- 阶段生产单 → 工具循环 → 真实产物 → 质量证据；
- 记录实际模型、首字时间、总耗时、Token、成本、格式首测合规率和重试结果。

真实 Key 已有本地秘密载体，但实施和测试不得读取后回显。没有可用 Key 时只能标记真实冒烟待验，不能用 mock 冒充。

### 11.3 浏览器与产品负责人验收

- 真实接口而不是最终 Mock；
- 加载、空数据、运行、待确认、失败、成功和恢复状态；
- 结果不存在时没有确认按钮；
- 刷新后回到同一阶段和待处理位置；
- 移动、平板、桌面目标宽度无横向溢出；
- 浏览器 Console 无持续应用错误；

## 12. 当前已知风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 三份手册上下文较长 | DeepSeek 首字时间较长、成本上升 | 稳定前缀缓存、阶段化完整加载、记录缓存和耗时，不压缩原文 |
| 当前 Worker 只生成一次文本 | 无法真实修改和验证产品 | 后续 Harness 阶段建设连续工具循环 |
| 现有数据库没有完整迁移系统 | 新状态可能破坏旧数据 | 先建立编号迁移和迁移测试，再扩展 schema |
| 未提交改动较多 | 重构容易覆盖用户工作 | 小步修改、避开无关文件、每阶段检查 Git diff |
| 九个固定确认点可能过密 | 用户感到流程冗长 | 试产记录确认耗时；只允许合并展示，不得静默跳过必要决定 |
| 动态 Shell 与文件写入 | 可能越界或破坏数据 | 工具网关、默认拒绝、路径边界、预算和人工确认 |
| DOCX / PDF 输入质量不一致 | 解析错误导致错误 PRD | 保留原文件、文本提取证据、失败提示；扫描 PDF 不静默处理 |
