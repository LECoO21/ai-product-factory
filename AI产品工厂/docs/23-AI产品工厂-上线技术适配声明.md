## 1. 上线结论

第一版继续定位为“产品负责人本人使用”，正式入口采用火山引擎 veFaaS 提供的 HTTPS 地址。为避免 Next.js Web 与 Worker 分开部署后无法共享 SQLite，线上把 Web、API 和单 Worker 放在同一个常驻应用实例内；SQLite、生产任务和产物目录统一位于 `/tmp` 的受控目录，并通过私有 TOS 做定期备份和启动恢复。

这不是高并发、多租户架构。出现第二位真实用户、并发 Worker 或重要生产数据规模上升时，必须先迁移到 PostgreSQL 和正式对象存储索引，再扩大使用范围。

## 3. 采用方案

| 能力 | 本项目方案 | 原因 |
| --- | --- | --- |
| 运行单元 | 单个 veFaaS Next.js standalone 应用，进程内启动一个 Worker | Web、Worker 和 SQLite 必须共享同一实例文件系统 |
| 公网入口 | veFaaS Application + Serverless API 网关 HTTPS 地址 | 符合手册默认路线，不先购买域名 |
| 登录 | 单产品负责人邀请码换短期签名会话，HttpOnly Cookie | 满足公网入口保护，同时不扩展团队和商业账户体系 |
| 数据 | `/tmp/ai-product-factory/factory.sqlite` + 预留实例 1 | 兼容现有 SQLite；只适合第一版单用户 |
| 恢复 | SQLite 一致性快照定期上传私有 TOS，启动缺库时自动恢复 | 不能把预留实例当作唯一持久化保证 |
| 文件 | 产物同步到私有 TOS；数据库只保存元数据和受控路径 | 文件资产与业务数据分离 |
| 手册 | 构建时复制到不受 Git 跟踪的私有部署包，线上仍做 SHA256 校验 | Factory Agent 运行时必须读取原文，公开仓库不能包含原文 |
| 日志 | JSON 结构化日志、`trace_id`、可选 Sentry 上报 | 用户看到简单错误，服务端保留可追踪元信息 |
| 发布 | 先准备代码和验证，再配置 Secret，最后首次发布并单独设置预留实例 | 避免首次发布顺序错误 |

## 4. 强制底线

- 密钥只进入 veFaaS Secret/环境变量；不得进入代码、前端、部署日志或 Git。
- 线上强制登录；未登录页面跳转登录页，API 返回统一 401。
- 第一版只允许一个逻辑产品负责人身份；不提供第二个邀请码或共享数据入口。
- SQLite 不直接复制正在写入的文件；必须先生成一致性快照，再上传。
- TOS 桶必须私有，产物通过受控后端接口读取，不生成永久公开地址。
- 三份原始手册只进入私有部署包，继续受 SHA256 校验；不得提交到公开仓库。
- 创建网关、预留实例、TOS、日志或其他计费资源前，必须明确资源名称、地域和费用影响。
- 发布失败不删除旧数据和旧版本；保留回滚入口与最近一次可恢复备份。

## 5. 费用与平台影响

veFaaS 默认按量后付费。官方当前国内地域价格显示：CPU 预留实例按 vCPU 和内存使用时长计费，调用次数与公网流量另计；例如假设规格为 1 vCPU + 2 GiB 且整月常驻，按公开单价计算约为 158 元/月，实际金额以控制台所选规格和账单为准。API 网关、TOS、日志、Sentry 和模型调用另行计费或按各自套餐计算。

正式创建资源前仍需在控制台核对实际规格、优惠和预计账单。本阶段不购买资源包，不绑定自有域名，不开非必要可观测性开关。

## 6. 偏离与暂缓

### 6.1 不拆成独立前后端应用

部署手册默认前后端可独立部署。本项目的 API 已由 Next.js Route Handler 提供，Worker 与 Web 共用本地 SQLite；强行拆开会立即破坏任务状态和数据一致性，因此第一版采用单一应用。迁移 PostgreSQL 后再重新评估拆分。

### 6.2 不在本阶段引入 PostgreSQL

第一版只有产品负责人本人，继续采用 SQLite 轻量方案。它依赖预留实例和 TOS 恢复，不承诺多实例并发。出现多用户、并发 Worker、实例扩缩容或数据价值上升时，PostgreSQL 迁移成为发布前置条件。

### 6.3 单一逻辑用户

部署手册要求登录和数据隔离；PRD 第一版明确不做多用户。本阶段用唯一邀请码建立唯一逻辑身份，任何未登录请求均不可访问业务数据。若增加第二个真实用户，必须先增加 owner 字段、行级过滤和 A/B 隔离测试，不能只增加邀请码。

## 7. 当前阻塞与解除方式

代码准备和本地验收不受阻塞。真实公网发布需要：

1. 完成火山引擎登录（优先 SSO，或在本机安全登录 AK/SK）；
2. 账号中存在或创建北京地域 Serverless API 网关；
3. 创建私有 TOS 桶并配置最小权限凭证；
4. 配置 `AUTH_SECRET`、`INVITE_CODES`、DeepSeek Key、TOS 和 Sentry 等线上 Secret；
5. 在控制台确认最终规格和费用后执行发布。

以上条件未满足时，只能宣布“发布候选已就绪”，不能宣布“已经上线”。
