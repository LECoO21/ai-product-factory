## 1. 本阶段完成结果

- 建立集中 API 层：统一 JSON 请求、超时、Zod 响应校验和 `AppError`；创建、启动、查询、确认、重试、调整和停止不再散落解释原始错误。
- 统一 Route Handler 错误外形：`code / userMessage / retryable / requestId / fieldErrors`。
- 建立统一任务状态：活动、等待用户、成功、失败、取消、断线和未知状态均有明确用户语言；未知状态不猜测成功。
- 建立集中 SSE 恢复层：按 sequence 去重；断线后先查询真实运行状态，再有限退避重连；SSE 恢复时立即发送连接握手。
- 运行页改为“真实状态 → 结果 → 产物 → 确认 → 折叠详情”；页面不直接显示 `succeeded`、Pi 或 Worker 等内部词。
- 失败时保留已有结果并提供真实重试入口；没有结果或失败批次不显示确认按钮。
- 需求少于 20 字时在输入区显示明确错误；提交中禁用重复操作。
- 测试使用隔离临时数据库，不修改历史生产记录，也不触发 DeepSeek。

## 2. 开发中发现并修复的问题

1. `ready` 任务断线仍显示“等待开始”：修正为“正在恢复连接”。
2. SSE 恢复后没有立即发送数据，浏览器无法确认连接已恢复：增加 SSE 连接握手。
3. 浏览器原生 `minLength` 会阻止自定义字段错误出现：表单改为统一业务校验并显示可读提示。
4. 失败批次已有部分结果时没有重试入口：保留结果并在结果底部提供重试。
5. 流事件 JSON 损坏可能造成页面异常：无效事件现在安全忽略，不污染真实状态。
